# 阶段六：正式回测作业的发布与恢复

本设计细化[框架计划阶段六](../plans/2026-11-14-research-backtest-pg-memory-framework.md#阶段六正式作业原子结果发布重算和取消闭环)，不替代 [ADR 0151](../../adr/0151-postgresql-business-publication-and-memory-work.md)。Constitution Impact：NO。

## 交付边界

交付单位是用户提交的一次正式回测：从现有调度器认领原 Run，到用户经正式 API 和 Web 查询其结果。本次不改经济规则、不启用实盘，不迁移持续交易持久化或全库清退 SQLite。只迁移回测路径的实际调用方及其有效测试。不覆盖工作树既有修改，不为历史格式保留文件 reader 或双写。

## 执行、恢复与读取

1. 复用现有有限作业的冻结绑定、认领、内存执行和发布仓储，不增加新服务。只使用原策略、程序、精确行情和参数；缺失或不匹配时不得换用最新版本。计算不持有长数据库事务。
2. 实际执行者确认子任务结束、事件排空及经济结果完整后，提交候选。由同一 PostgreSQL 事务校验有效 Attempt、租约及绑定，写入全部成员、唯一发布和 Run/Attempt 终态。拒绝过期执行者、错成员、缺成员；失败事务不暴露部分内容。
3. 中断后先观察原 Run。已发布则读取；确定未发布且可重新认领时以新 Attempt 从冻结输入重算；提交未知则继续观察，不能直接重算、创建新 Run 或报成失败。沿用现有重试上限。重复执行不能改变经济身份。
4. 取消与发布按事务顺序裁定：取消先完成，只保留状态和原因；完成先发布，迟到取消不能撤销结果。取消请求尚未裁定不等于已取消。前端不展示部分指标或伪零收益，未知时允许继续查询原 Run。
5. 正式 GET 在权限边界内只读完整 PG 发布，不启动执行、不打开文件；资格审查等直接消费者不得引用候选。同步演进受影响的 API 契约、生成客户端及 Web 测试。

## 验证与停止条件

- 在同一冻结源码下先定位已有发布矩阵的 Research 前置失败，再证明真实 Backtest worker 确实执行并发布；分别记录前置与目标场景，不能以其中一个通过替代另一个。
- 固定 onlyalpha-dev 验证阶段六规定的中断、取消、事务回滚、响应丢失和旧租约矩阵。断言 Run、Attempt、发布数、结果成员、经济内容、权限及重复 GET 的执行次数；Web 经正常入口验证完成与取消呈现。
- 记录受影响链路分段耗时、源码身份、验证日志及独立审查结论。不以旧快照、模拟仓储或仅编译作为放行证据，不另设性能门槛。
- 工作树归属或基线不明时不覆盖、重置或推送。资源压力或同一阻塞三次未解决时按工程规则停止。缺少固定环境或独立审查则标明未验收；本次通过不等于框架阶段七至九完成。
