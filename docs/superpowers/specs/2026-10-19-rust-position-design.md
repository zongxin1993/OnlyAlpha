# Rust Position component design

## Authority and scope

One independently buildable `crates/onlyalpha-kernel/position/` library groups account Position, Cluster Allocation/Unallocated, sell Reservation, restrictions, explicit settlement and Broker comparison. Only Domain is a local dependency. Rust remains a non-activated component; official Runtime, economic transaction durability, database formats, Python modules and LIVE authority do not change. Version remains 0.10.10; no Release.

## Input and ownership

An exact immutable configuration binds engine/runtime/account/gateway/generation, allowed clusters, currency and instrument precision/multiplier. Versioned closed component commands bind that context, command ID, cause fingerprint and explicit nanosecond time. Instrument, cluster, order and external trade identities remain scoped. Domain parses identifiers, currency and dimensional values; arithmetic inputs are bounded before arithmetic. No network, clock, callback, broker SDK, storage or market branch enters the library.

One manager single-writes all Position responsibilities but keeps ownership distinct: account quantity/cost equals the sum of Cluster allocations plus Unallocated; one attributed Close decision supplies released cost and realized PnL to both. Missing Cluster Open is explicitly Unallocated, never assigned implicitly; active Unallocated closes remain unsupported, as in the current owning Contract. Unsupported HEDGING/Short/Inverse/FIFO fail closed. Market calendars, settlement timing, fee decisions and order terminal-Fill decisions are external explicit inputs.

## State and transitions

NETTING Long-only supports open/increase/partial close/full close/new cycle, explicit SETTLED/UNSETTLED buckets, restrictions with effective intervals, and conservative Broker availability. Position identity is a hash of exact owner key and cycle, avoiding delimiter collisions. Closed histories and cycles survive fresh restore. Cost is exact Decimal accumulation, never reconstructed from rounded average. Close releases the owning Allocation proportional cumulative cost under the existing close reducer's significant-precision policy (at least 36 digits, coefficient digits +12, or 2*quantity precision +18); final close releases all remainder. Price and Money views use one half-even rounding.

Sell Reservation owns original/consumed/released/remaining quantities, order/cluster/instrument relation and monotonic LOCAL_ONLY, SENT_TO_BROKER, BROKER_ACKNOWLEDGED, RELEASE_PENDING, RELEASED stages. Both account and cluster availability gate creation. Account local hold stops being deducted after acknowledged broker hold; cluster hold persists. Close consumes only its exact reservation in the same atomic update; explicit terminal_fill comes from the caller's Order authority. A terminal Fill releases excess reservation; partial Fill retains remainder. Terminal release without broker confirmation keeps uncertain holds. Repeated commands require retained exact payload proof; unseen commands do not become DUPLICATE merely because state coincides.

Broker snapshots retain total/side/buckets/available/frozen/average/source identity without replacing local economics. Quantity/side/bucket conflict blocks the instrument; availability/frozen delay is a warning, cost difference informational. Unavailable/malformed/foreign/stale proof never clears a block. An explicit fresh matching comparison can clear a reconciliation block but never override a stale unapplied trade; missing observations are not certified absence. Valid observed fills can still update blocked holdings subject to exact settled quantity and reservation ownership; new reservations fail closed. Reconciliation does not distribute Broker discrepancies into fake trades.

## Atomicity and recovery

Apply validates strict schema/context, command and external receipts, ordering and numeric bounds. It clones bounded component state, computes the full candidate, verifies economic/hold invariants and capacity, then commits once and returns a causal immutable fact. INVALID/CONFLICT do not mutate. A STALE external trade records a deduplicated reconciliation-required observation, changes no economics and blocks availability; it remains journaled and recoverable, never acknowledged as economically applied. External receipt aliases retain full payload fingerprints and reject conflicting reuse. Query results are detached immutable values, with separate account, exact cluster and owner-only Unallocated access.

Checkpoint schema1 commits exact config, full applied/observed journal and complete derived state including receipts, cycles, restrictions, reservations, broker observations and closed history. Restore requires externally supplied digest, canonical encoding and exact config, replays into fresh state, checks all derived state and swaps atomically. Digest is an integrity trust root, not authentication. No legacy loader, automatic history migration or business data mutation.

Bounds: 32 instruments, 32 clusters, 256 allocation lifecycles, 512 reservations, 4096 journal records, 16KiB command, 4MiB journal and 16MiB checkpoint. Input coefficients at most 128 digits, exponent -64..64; derived arithmetic/cost state at most 1024 digits and exponent -512..512. Capacity is checked before mutation; this bounded comparison library is not production capacity admission.

## Python audit and comparison

Direct Manager aliases only remember IDs, mutate entities before all validation, restore incrementally, and direct Close does not release canonical cumulative cost. Rust must not copy these reference defects. Valid common opens compare actual Python Position/Allocation Managers; Close cost compares the actual owning `only_reduce_average_cost_close` reducer, independent literal vectors and Rust results. Mixed-cluster conservation, reservation ownership, full payload conflicts and restore mutations have independent tests. Scope-specific Linux frozen-source debug/release, Clippy, isolated Domain+Position closure, affected Python tooling/lane tests, bounded simplicity and one independent Authority review are required. Official activation and end-to-end durable economic transactions remain subsequent work.

## Advisory failure evidence

Curated FP-DATA-001 (TqSdk #72/#73) shows replayed/stale Position observations must not become current truth; this design derives payload-aware receipts, Broker ordering/quality rejection and sticky unapplied-Trade blocking tests. FP-STORAGE-001 shows a current Position snapshot is insufficient causal history; the complete component journal and fresh replay tests preserve source facts and closed cycles. These are failure lessons, not borrowed provider cleanup/retry implementations; official durable transaction and deployment upgrade remain separate gates.

Successful duplicate responses for new command IDs retain durable acknowledgement receipts without changing economic versions, business time or emitting a Position fact; such IDs cannot later bind another command. Replay admits these distinct acknowledgement occurrences and rejects a repeated journal command that adds no receipt. Account, Cluster and Unallocated Position identities use disjoint structured owner-family tags. Reservation acknowledgement is retained independently of release-pending stage; cancellation after send preserves uncertain holds, and a late ack does not cancel release-pending intent. Available quantity satisfies both local settled-minus-independent-restrictions-minus-all-holds and Broker available-minus-unacknowledged-local-holds constraints. Every accepted stale Broker observation also retains its immutable payload receipt.

The component has no business-time observation while its journal is empty (`now: null`). Its first accepted input explicitly initializes time, including signed pre-1970 nanoseconds; subsequent local commands cannot regress it. No wall clock or implicit Unix-epoch floor participates in the state transition.
