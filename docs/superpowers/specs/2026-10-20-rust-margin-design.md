# Rust Margin design

One Domain-only library owns immutable collateral reservations and deterministic RESERVE, OCCUPY, RELEASE_RESERVED and RELEASE_OCCUPIED transitions. Compiled market requirements are explicit instruction inputs; rate/model selection stays in Plugin/adapters. Scope binds Engine/Runtime/Account/Gateway/Generation/kind/Cluster/Revision/Instrument/Request, plus immutable mode/isolation/position side and source identities. No rate default, absent-proof acceptance or market-specific branch is introduced.

RESERVE establishes exact quantity precision and a funding envelope. OCCUPY consumes only the same Order's reservation. RELEASE_RESERVED cancels only that reservation's remaining quantity/funding after an explicit terminal proof. RELEASE_OCCUPIED names one opening reservation, the closing Order/Trade and exact quantity; cross-account/side/isolation borrowing is forbidden. Multiple opening reservations are released via explicit per-reservation allocations. Partial collateral and maintenance releases use integer minor-unit HALF_EVEN allocation; final release consumes the exact remainder.

Immutable command receipts, exact expected version/before hash, alias uniqueness and atomic candidate replacement enforce determinism. A global maximum of 512 history slots is pre-reserved from canonical quantity quanta (two per quantum plus reserve/terminal). A valid positive fill/close cannot increase the remaining worst-case budget. Bounded scope/commands/records and a 32 MiB checkpoint keep recovery and existing safety progress representable. Recovery replays immutable commands into a fresh candidate and compares the whole resulting checkpoint before installation.

Execution consumes the opaque Margin result, verifies real Order/Trade relationships and commits Margin checkpoint plus Account collateral projection in its existing six groups. Account availability deducts collateral without changing cash/equity or inventing a parallel Margin authority. Metadata schema evolves explicitly; historical isolated codecs are not official production readers. Existing cash-security Fill semantics remain, and this consumer proof does not admit a complete futures Runtime.

Python Margin is a classified common reference, not an oracle: whole-scope release and restoration permissiveness must not be copied. Existing contracts and ADR 0026/0057/0139 retain authority. Native component identity remains distinct from Python history identity. Required migration/history/deployment admission remains with R3–R8; this library never activates Runtime or LIVE.

Consumer inputs explicitly declare collateral NONE or MARGIN; missing proof never implies zero. Reserve is part of ADMIT, occupancy and close release part of FILL, and unfilled remainder release part of TERMINAL (including immediate terminal-fill remainder). Close input explicitly selects RESERVATION_ID_ASCENDING plus exact mode/isolation/side; the consumer derives bounded instructions from owned records and quantities, avoiding an external unbounded allocation frame. The current LONG/NETTING consumer rejects concurrently mixed active collateral pools for one Position scope rather than inventing separate Position authority. This restriction does not reduce the independent Margin library's complete modes/sides.

Python Order Adapter's cancellation/close reservation selection is corrected only where source-trade presence provides a real operation distinction; native allocation/quantity and strict history invariants remain independently specified rather than claimed whole Python parity.

Account 的 Margin writer 仅接受 `onlyalpha_margin::Effect`，不接受可写 derived before/after。必要依赖为 Account → Margin → Domain；Margin 仍只依赖 Domain。Account journal 保存 producer config/capacity、完整 producer checkpoint before/after digest 和 canonical input，每次消费及 fresh recovery 都由 Margin 重推导并校验完整历史连续性。
