## Reference audit and identity boundary

ADR0069/0070 define Calculation identity, strict tagged persistence and exact backend resolution. Audit Python definition.py, graph.py, compatibility.py and registry.py plus Indicator/Cluster callers. Python semantic_payload uses untagged Decimal-as-string values: Decimal("1") and string "1" collide, while Decimal("1.0") differs from Decimal("1"). Constructors admit invalid empty port/reference names and non-hex 64-character fingerprints; parameter STRING converts arbitrary objects; Python recursion limits graph depth. These behaviors are reference deviations, not Rust requirements.

Rust Definition **component schema3** hashes its complete normalized tagged record using canonical sorted-key UTF-8 JSON and SHA-256. Decimal tags remain distinct from STRING and INTEGER; finite decimals use exact normalized plain text, signed zero becomes zero. Numeric output quantum preserves its effective Decimal exponent: 0.01 and 0.010 remain distinct, as do 1E+2 and 100; lexical aliases with the same coefficient/exponent normalize identically. Scalar value normalization never applies to quantization metadata. No untagged hash, legacy reader, Python schema2 fallback or dual official writer is introduced. This explicit identity evolution is NOT admitted to Python Definition2, existing Runtime Generations, Strategy Revisions or historical artifacts. Actual transition requires exact reference/consumer and history migration proof in a separately scoped integration task; existing artifacts/data are untouched. Common vectors compare semantic content and validation/graph/registry behavior; Python2 fingerprint equality is explicitly not claimed. Independent expected hashes exercise Rust3; Python production constructors read projected valid rows and are checked against independent values.

## Contracts

Public immutable Definition and TypeDefinition wrappers own validated serde_json records and return clones or shared read-only references. No public unchecked field mutation. Validate borrowed nested leaves before copying any caller-owned Value; malformed deep containers must return errors rather than recurse through Clone. Rust TypeDefinition component schema1 contains kind/type_id/semantic_version, parameter schema, input/output ports, missing/timestamp/numeric/factor/execution shape contracts. Parameters have exact tagged defaults/bounds/enums and declared INTEGER/DECIMAL/STRING/BOOLEAN. Required has no default; optional requires nonnull typed default. Normalize explicit raw inputs: integer number or integer text, decimal number/text without floats, strict string and Boolean. Unknown/missing parameters fail. Exact finite bounds and enum membership use declared normalized type; uppercase is ASCII-only and rejects non-ASCII input rather than depending on platform Unicode version. Non-uppercase strings retain Unicode. Invalid metadata/defaults reject before registration. Definition input/output array order remains semantic, maps are sorted, no alias/runtime/implementation enters identity. Execution-shape extension must agree with factor_kind; non-Factor defaults TIME_SERIES. FACTOR_SCORE bounds are [0,1], distinct from legacy trading score models.

Names nonempty/no whitespace, dotted ASCII lowercase type identifiers with nonempty segments, versions nonempty/no whitespace; references select exactly one nonempty external source or lowercase 64-hex node plus output name. Ports validate datatype/nullability/nonempty unique dimensions/semantic/unit. Required warmup observations/precision positive; no readiness capability follows. Numeric representation and rounding are explicit metadata, not claims that a backend exists. One documented input budget4096 bounds collection counts, strings, integer digits and decimal coefficient/exponent; this is a Rust component admission budget, not a changed Python algorithm period policy.

Graph schema1 rows contain exact schema3 Definitions and optional presentation aliases. Reject duplicates, missing edges/outputs, incompatible datatype/nullability/dimensions/semantic/unit, Target/Feature mixtures and Target node dependencies. PREDICATE_OPERAND wildcard is input-only for semantic/unit, never dtype/dimensions/nullability. Deterministic iterative DFS mirrors Python sorted roots and sorted reference traversal without host recursion. Semantic fingerprint excludes aliases and uses ordered normalized Definition records; graph record preserves aliases. Empty graphs follow current Python behavior.

Registry<P> stores actual caller-owned provider values without invoking them: exact (kind,type,version,TRADING|RESEARCH), one identical TypeDefinition across backends, atomic duplicate/conflict rejection, stable type/registration introspection and exact resolution. It grants no execution, readiness, worker availability, generation admission or certification. No implicit latest, factory, loading or fallback. There is no process transport or generic future resolver interface.
