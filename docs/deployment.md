# 开发部署

[开发 Compose 配置](../deploy/docker-compose.dev.yml)定义 `onlyalpha-dev` 的 PostgreSQL 和 ClickHouse 服务、各自的数据卷与内部网络。原 Backend 的 API、Worker、Agent 接线、应用镜像与验证容器均已退役。依赖服务的 Web、OpenAPI、发布和恢复流程暂停。

## 开发与数据

Rust 开发、编译和单元测试在 Mac 主机原生执行。需要数据库时使用本机现有开发环境和已配置的连接；库单元测试无需数据库。当前 Compose 文件不发布主机端口，实际连接地址以环境现有配置为准。数据库可用仅证明相应服务可访问。

PostgreSQL 保存正式业务、发布与控制事实，ClickHouse 保存行情正文。运行数据、凭据、密钥与源码分开管理。数据库、文件、密钥和命名空间有配对关系时，备份、验证和恢复均需核对原始身份与引用。开发数据重建的归属、生命周期锁及保留条件见[工程指南](../AGENTS.md#42-开发环境重建与正式数据)。

## 产品部署约束

正式产品宿主恢复后，Web 和 Agent 通过带身份与权限检查的版本化 API 操作。Source 授权、连接保密、物理发送前权限校验、角色隔离与实际发布证据仍然适用。Agent 需要真实部署配置、明确授权和安全传输，不能借本地开发网络放宽正式部署要求。

后端启动须验证已配置的数据库及存储身份、权限、版本和 schema；迁移、角色授权、数据初始化和清理必须显式实施。服务健康、进程启动、数据库提交、结果发布和灾难恢复分别取证。正式发布与恢复约束见[有限作业契约](job-execution-contract.md)和[PostgreSQL 存储说明](postgresql-job-publication.md)。
