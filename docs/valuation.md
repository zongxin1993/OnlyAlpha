# Rust mark valuation

Valuation is a logical responsibility in the Position library. Position owns consolidated quantity, exact remaining cost, cycle and realized attribution; each Strategy Ledger owns its Cluster cash/equity projection and consumes only its own Allocation. Account is the consolidated cash/equity owner. Valuation never owns cost or realized PnL and introduces no additional Runtime writer.

`Position::Manager::value` accepts a closed schema1 intent with valuation identity, positive version, current Account economic version, complete Position checkpoint digest, explicit time and complete marks. Each observed instrument, including a retained closed book, requires one mark. The empty set proves zero only for a complete empty Position owner. A mark binds canonical instrument, positive precision-valid price, CLOSED_BAR family, stable source reference, positive version, explicit time and source sequence. Missing, extra, duplicate, future or economically stale inputs fail closed. No live clock or price fallback is read.

For each consolidated Position, market value is quantity × mark × configured multiplier rounded once HALF_EVEN to base currency precision. Unrealized PnL is that monetary market value minus exact Position cost × multiplier; fractional cost residuals remain exact. Account totals sum those consolidated lines. Cluster Ledgers retain their own Allocation cost and round their own marked quantity. Per-line rounding can make the sum of Cluster market values differ from consolidated Account market value; valuation does not silently repair that difference or certify aggregate reconciliation.

`ValuationEffect` has private fields. A live canonical Position owner produces it; public callers cannot author derived market value/equity/PnL. Its replay input binds the full Position checkpoint and original intent. Re-derivation validates and replays that source before computing the result. Checkpoint digests are integrity evidence, not external producer authentication. The Execution composition binds the supplied digest to its exact current Position owner; a standalone source checkpoint does not establish membership in an arbitrary Runtime.

Account config schema2 pins the exact Position configuration fingerprint. Its applied Trade index binds each Trade to the Position snapshot evidence, cause, time, Order, Execution, venue Trade and sequence already consumed by Account. The producer replays Position history to derive that same complete applied-Trade relation. A same-scope replacement history, omitted/extra Trade or changed instrument configuration cannot author Account equity.

Account accepts only a typed ValuationEffect at its public valuation writer. Its internal journal re-derives the source, checks engine/runtime/account/gateway/generation/currency, input time, exact current economic version and increasing valuation version, and replaces market value/unrealized only. Cash, fees, realized PnL, rounding residual, receivables, reservations and Margin remain unchanged. Account checkpoint schema4 has no raw derived valuation fallback.

Execution VALUATION is one account-wide barrier. Its normal envelope retains the initiating Cluster/revision for causality; it values every configured Cluster, including empty ones, against the same instrument marks. It checks complete Allocation identity/cycle/version/cost/quantity/realized relation before invoking the Ledger-owned reducer. For new facts, per-instrument mark version/source sequence increase and event time cannot regress. The exact unchanged fact may be explicitly reused; a source reference can never author different facts, and no mark exceeds the barrier sequence. Metadata is re-derived from the Account valuation source journal on Ready restoration and final projection installation. A pending prefix checkpoint remains non-business-visible while its forward recovery completes; mixed prefix owners are not mistaken for a finished valuation. Account-wide barrier identity derives separate scoped Ledger valuation identities without weakening global aliases. Up to32 Clusters fit into64 ordered occurrences per input. Execution metadata schema5 preserves these source watermarks. The existing Store/Prepared/ordered projection/Ready protocol commits all owners atomically; recovery never exposes an installed prefix or manufactures a Trade, fee, cash flow or collateral transition.

This isolated component contract does not activate Rust in the official Runtime, retire Python, migrate official business history, certify Shipping Web acceptance, add FX/funding/liquidation or change LIVE authorization. Fill accounting retains its existing explicit input contract. Python Position valuation uses rounded average-price PnL; only the common exact-cost subset is parity evidence. Independent exact-cost/tie vectors define the native residual requirement rather than treating the older rounded Python result as an oracle.

Engineering references are advisory: [LEAN stale-price issue #2762](https://github.com/QuantConnect/Lean/issues/2762) motivates rejecting a mark predating consumed economics rather than inventing a fresh price. [Nautilus position-flip PnL issue #1083](https://github.com/nautechsystems/nautilus_trader/issues/1083) motivates preserving exact cycle/cost identity across close and reopen. These lessons become deterministic source/version/cycle regressions; provider fill models, position-flip policy and upstream patches are not adopted.
