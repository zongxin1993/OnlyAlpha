# 0. 任务定位

你正在修改 OnlyAlpha。

# 5. 第一性原理问题

当前 Agent 容易形成：

```text
实现一点
↓
full release
↓
等待
↓
发现小问题
↓
修改
↓
full release
↓
等待
↓
最终 exact-SHA Certification 再完整跑一次
```

问题包括：

1. 与 change 无关的 heavy lanes 被反复执行；
2. 成功 pytest stdout / durations / CI polling 占用 Agent context；
3. 局部错误反馈周期过长；
4. development proof 和 certification proof 重复。

P7.5.2 必须把验证拆成不同 authority level。

# 6. 四级验证模型

## Level 1 — Targeted / Inner Loop

用途：

```text
implementation feedback
```

运行：

```text
直接修改的 tests
直接受影响的 unit / contract / architecture tests
```

建议使用 concise failure-first 模式，例如：

```bash
pytest <target> -q --tb=short --maxfail=1
```

它只证明局部实现，不得用于声称 stage ACCEPTED。

## Level 2 — Canonical Component Gate

局部实现稳定后运行对应现有 canonical lane：

```text
Calculation          → calculation
Research Calculation → research-calculation
Research Job         → research-job
Research Factor      → research-factor
Research Dataset     → research-dataset
Streaming Recovery   → recovery + sim-recovery
Trading Core         → core-full
```

必须复用 `scripts/test_suite.py` 的正式 lane 定义。

## Level 3 — Impact-Aware Local Gate

根据 change set 计算：

```text
Required Static Checks
+
Required Canonical Lanes
+
Required Build / Architecture Checks
```

这是保守、可解释、可审计的 local verification plan。

它不是 certification。

## Level 4 — Final-SHA Certification

最终 immutable SHA 必须继续执行：

```text
ALL mandatory certification gates
```

P7.5.2 不得减少：

```text
mandatory canonical lanes
coverage
Semgrep
CodeQL
build
exact subject SHA verification
```

任何 missing / skipped / cancelled / failure 继续意味着 REJECTED。

# 7. Impact Selection 不是 Test Authority

Impact planner 只能回答：

> “开发阶段，这个 change 至少应该验证哪些正式 gates？”

不能回答：

> “最终认证可以跳过哪些 gates？”

必须保持：

```text
Impact Planner
    ↓
local subset only

Final-SHA Certification
    ↓
full mandatory matrix
```

这条边界必须通过 docs + tests + workflow structure 固化。

---

# 8. 禁止第二套 Canonical Lane Authority

当前 lane semantics 已由 `scripts/test_suite.py` 或当前等价组件拥有。

禁止新增工具复制：

```text
pytest paths
marker expressions
worker counts
coverage definitions
```

形成第二套：

```text
agent lane semantics
≠
canonical lane semantics
```

新的工具只能选择：

```text
lane name / existing lane object
```

真正的：

```text
paths
markers
workers
coverage
```

仍由唯一 canonical owner 管理。

如当前结构不方便复用，允许最小重构以建立唯一 owner。

# 9. Deterministic Change Set Contract

Impact planner 必须明确分析哪个 change set。

建议提供显式模式，例如：

```bash
uv run python scripts/verify.py plan --base <base_sha>
```

需要明确定义是否包含：

```text
base_sha..HEAD
staged tracked changes
unstaged tracked changes
untracked relevant files
renames
deletions
```

要求：

- deterministic；
- dirty worktree 不得被静默忽略；
- normalized path order 固定；
- 输入顺序不能改变结果；
- resolved base 必须显示；
- invalid base fail closed。

v1 优先使用显式 `--base`，避免隐藏 branch 假设。

# 10. Explicit Impact Rules

禁止把以下机制作为 authority：

```text
LLM guessing
opaque heuristic
ML test selector
historical correlation
```

推荐明确、typed、可审计的 rule，例如：

```python
@dataclass(frozen=True, slots=True)
class OnlyVerificationImpactRule:
    pattern: str
    required_lanes: tuple[OnlyTestLane, ...]
    required_checks: tuple[OnlyVerificationCheck, ...]
    rationale: str
```

名称可根据当前代码调整。

每个 rule 必须能解释：

```text
changed path
→ matched rule
→ selected gates
→ rationale
```

---

# 11. Rule Merge 必须单调

多个 changed files / rules 命中后：

```text
required gates = deterministic union
```

要求：

- never subtract；
- high-risk rule 不能被 low-risk rule 降级；
- 无重复；
- stable canonical order；
- 不依赖 set / filesystem / hash seed。

例如：

```text
file A → research-job
file B → research-calculation + research-factor
```

最终 plan 必须稳定地包含三者。

# 12. Unknown Impact 必须 Fail Closed

这是核心 safety invariant。

未知 production path：

```text
src/onlyalpha/new_unknown_core/**
```

不得：

```text
no rule match → no tests
```

必须升级到正式 conservative fallback，例如：

```text
BROAD / FULL_LOCAL
```

具体 fallback 需要结合当前 repo 重审。

原则固定：

> **No match != no impact.**

# 29. 推荐核心数据模型

优先 immutable typed models，概念例如：

```python
@dataclass(frozen=True, slots=True)
class VerificationChangeSet:
    base_revision: str
    head_revision: str | None
    changed_paths: tuple[str, ...]
```

```python
@dataclass(frozen=True, slots=True)

    escalation: VerificationEscalation
```

```python
@dataclass(frozen=True, slots=True)
class VerificationPlan:
    change_set: VerificationChangeSet

```

```python
@dataclass(frozen=True, slots=True)
class VerificationOutcome:
    plan: VerificationPlan
    results: tuple[VerificationStepResult, ...]
```

这些只是方向。

不要机械套用。

避免核心模型使用：

```python

```

# 32. Process Execution Contract

agent verification runner 调用 subprocess 必须：

- 保留原始 exit code；
- command 可审计；
- cwd 明确；
- environment 明确；
- full output 落盘；
- log persistence failure 不得把 test failure 误判 PASS；
- 任一 required gate failure → overall failure；
- SIGINT / termination 不应被错误吞掉；
- v1 使用 deterministic sequential gate execution 即可。

不要默认再做：

```text
parallel lane orchestration
+
lane 内 xdist
```

导致 CPU 过度竞争。

现有 lane 自己已有 worker strategy，应尊重现有 authority。

# 33. Local Failure Semantics

至少区分：

```text
PLAN_ERROR
```

例如：

- invalid base；
- Git change set 无法解析；
- malformed impact rule。

```text
VERIFICATION_FAILED
```

例如：

- static fail；
- selected canonical lane fail；
- build fail。

```text
VERIFICATION_PASSED
```

所有 local required gates success。

绝不能把：

```text
VERIFICATION_PASSED
```

写成：

```text
CERTIFIED
ACCEPTED
```

# 34. Architecture / Safety Tests

P7.5.2 必须增加长期有效的 tests。

至少覆盖：

## A. Input-order determinism

相同 changed paths 不同输入顺序：

```text
same plan
```

## B. Rule union

多个 rule：

```text
union all required gates
```

## C. Unknown production path

必须升级。

## D. Verification infrastructure self-change

例如修改：

```text
scripts/test_suite.py
```

必须进入最宽本地策略。

## E. Docs-only

纯 docs/prompts 不无意义运行所有 Runtime tests。

## F. Shared core change

必须 broad enough。

## G. Canonical lane reuse

planner 引用正式 lane authority，而不是复制 paths/markers。

## H. Stable fresh-process behavior

不同 hash seed / process 不改变 plan。

## I. Dirty worktree

不能静默忽略。

## J. Rename / delete

有确定 impact semantics。

## K. Multiple risk levels

高风险 escalation 不被低风险 rule 降级。

# 52. 最终原则

P7.5.2 的成功标准不是：

> “以后测试少跑一些。”

而是：

> **Agent 在开发阶段能够用一个 deterministic、explicit、conservative、fail-closed 的 impact plan，只执行当前 change 所要求的最小合理 local verification；完整 repository proof 仍然只在 immutable exact-SHA Final-SHA Certification boundary 完成。**

最终应该从：

```text
Implement
↓
Full Release
↓
Fix
↓
Full Release
↓
Fix
↓
Full Release
↓
Final-SHA Full Verification
```

变成：

```text
Implement
↓
Targeted
↓
Affected Canonical Lanes
↓
Impact-Aware Local Gate
↓
Final Commit
↓
Full Exact-SHA Certification
```

必须始终成立：

```text
Less redundant verification
≠
Less verification authority
```

以及：

```text
Agent efficiency
without
correctness compromise
```

这就是 P7.5.2 的最终验收标准。
