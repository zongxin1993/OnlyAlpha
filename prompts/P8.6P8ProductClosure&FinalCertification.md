任何正式事实只能有一个权威来源。

目标 Authority Matrix 应继续保持类似：

```text

→ Research Domain

→ immutable Dataset Snapshot authority

→ Calculation domain / Calculation Registry contract

→ immutable Statistics Result

→ immutable Research Result

portable/read projection
→ immutable Research Artifact

Research Run lifecycle
→ PostgreSQL Research Run authority

Attempt / lease / fencing
→ PostgreSQL Research Run Attempt + server clock

→ diagnostics only

→ existing application StopController

Research semantic execution
→ OnlyEngine → OnlyResearchRuntime
```


# 8. P8.6.0 — Final Correctness Closure

## 8.1 目标

在最终产品认证前，重新审计并关闭所有**已知且可复现**的 correctness / determinism 边缘缺口。

重点不是“大扫除”，而是找真实 invariant violation。

---

## 8.2 Stop / Claim Linearization

当前必须严格证明：

```text
stop 被 authoritative worker service 观察
→ 在 claim transaction 开始前
→ 不允许再开始新的 claim
```

明确 linearization contract：

```text
Case A:
stop observed before scheduler.claim_once begins
→ stop wins
→ draining
→ no new claim

Case B:
claim_once has already begun authoritatively
→ claim is in-flight
→ do not fake-cancel it
→ retain heartbeat ownership
→ drain to safe completion/cancellation/ownership-loss boundary
```

### 必须重新检查两个 stop 来源

1. 外部 process stop authority：
   ```text
   OnlyApplicationStopController / equivalent current authority
   ```

2. `OnlyResearchWorkerService.stop()` 自身内部状态。

不要只证明 signal path。

### 必须有 deterministic interleaving tests

至少覆盖：

```text
A. external stop arrives during housekeeping/reconciliation
   → no claim

B. service.stop() called concurrently during housekeeping
   → no claim after stop is observed

C. stop arrives only after claim has authoritatively begun
   → current claim drains
   → next iteration claims nothing

D. stop is idempotent
   → no duplicate state transition / duplicate harmful side effect
```

测试不得靠大量 `sleep()` 猜时序。

优先使用：

```text
Event
Barrier
explicit callback barrier
deterministic fake boundary
```

### 修复原则

如果当前代码已经完全满足：

```text
只补证明。
```

如果存在 race：

```text
在现有 Worker Service / Stop authority 中做最小修复。
```

禁止新增：

```text
ShutdownManager
WorkerLifecycleCoordinator
ClaimGateService
```

---

## 8.3 API / Worker Research Capability Equivalence

当前 API 与 Worker 是不同进程，因此不要求共享同一个 Python object。

真正不变量是：

```text
same installed deployment environment
→ API admission visible RESEARCH semantic capabilities
==
Worker execution visible RESEARCH semantic capabilities
```

### 必须建立 canonical capability projection

只比较正式 semantic contract，例如：

```text
type_id
semantic_version
Calculation kind
RESEARCH backend availability
declared input contract
declared output contract
必要的 formal semantic metadata
```

不要把以下 deployment/provenance metadata 当 semantic identity：

```text
Python class repr
module path
wheel filename
entry-point group ordering
Git path
repository name
object id
memory address
```

### 测试要求

至少证明：

```text
API composition projection == Worker composition projection
```

并且：

```text
different semantic capability
→ mismatch is detected
→ fail closed
```

不要为了这个测试增加中央数据库 Registry。

### 允许的最小重构

只有当 conformance test 证明当前 API 与 Worker composition wiring 的确存在可避免漂移时，才允许抽取一个**最小、纯 composition primitive**。

禁止提前设计：

```text
CompositionManager
CapabilityRegistryService
RegistryFactoryFramework
HotReloadCoordinator
```

# 12. P8.6.4 — Restart / Crash / Recovery Certification

## 12.1 第一性目标

证明：

```text
Process lifetime
!= Research truth lifetime
```

以及：

```text
same durable facts at recovery boundary
→ same recovery decision
→ same final semantic truth
```

---

## 12.2 Fault Injection 原则

优先：

```text
subprocess/process kill
explicit deterministic barriers
test harness orchestration
existing injectable port boundaries
```

禁止为了测试在 production Domain 大量增加：

```python
if TEST_MODE:
    crash_here()
```

禁止靠：

```text
sleep(10)
希望刚好 crash 在正确位置
```

最终 fault tests 必须尽可能 deterministic。

---

## 12.3 必须覆盖的 Fault Matrix

### F1 Browser refresh

```text
RUNNING
→ Browser refresh
→ execution unaffected
```

### F2 Browser close

```text
RUNNING
→ Browser exits
→ execution unaffected
```

### F3 API restart

至少在：

```text
QUEUED
RUNNING
COMPLETED
```

状态下验证 API restart 不改变 authoritative Run truth。

### F4 Worker idle restart

```text
QUEUED exists
→ Worker restarts
→ fresh process composition
→ claim still deterministic
```

### F5 Worker crash after claim

```text
Attempt ACTIVE
→ Worker process dies
→ heartbeat stops
→ lease expires using PostgreSQL server clock
→ stale Attempt never revives
→ fresh Attempt claims/re-enters
```

### F6 Worker crash during semantic execution

```text
crash during Calculation/Research execution
→ no fake local finalization
→ lease recovery
→ deterministic re-entry
```

### F7 Crash after immutable Calculation Result commit

```text
Calculation Result exists
→ Worker dies
→ recovery
→ verified exact reuse
```

不得因为 process lost 就重写 immutable truth。

### F8 Crash after Statistics Result commit

同样证明 exact reuse。

### F9 Crash after Research Result commit

```text
Research Result exists
Run not yet finalized
→ recovery reads/verifies existing Result
→ no duplicate semantic truth
```

### F10 Crash after Artifact commit, before Run COMPLETED finalization

这是关键场景：

```text
Result committed
Artifact committed
Run not COMPLETED
Worker dies
↓
fresh Attempt
↓
verified Result + Artifact reuse
↓
fenced finalization
↓
COMPLETED
```

### F11 stale Worker return

```text
old Attempt expired
new Attempt owns Run
old Worker returns late
→ fencing rejects old write
```

### F12 cancellation vs completion race

遵守当前 semantic-fact-first cancellation contract：

```text
authoritative complete evidence exists
→ completion can win according to current contract

absent/partial semantic evidence after cancellation recovery
→ cancellation convergence according to current contract
```

不要凭“哪个线程先执行 Python 代码”决定。

### F13 temporary PostgreSQL outage

验证：

```text
known StoreUnavailable
→ stable operational classification
→ bounded retry where policy owns retry
```

### F14 heartbeat / ownership uncertainty

```text
heartbeat/Execution Store timeout
→ Worker cannot prove ownership
→ no local authoritative finalization
```

### F15 immutable corruption

```text
corrupt Dataset / Result / Artifact
→ deterministic fail closed
```

不得归类成普通 transient retry，除非 current formal contract 明确定义。

---

## 12.4 不增加恢复状态

除非发现新的 durable domain fact，禁止新增：

```text
RECOVERING
STUCK
LOST
ZOMBIE
RETRYING
```

`stuck` 若当前只是诊断，继续只是诊断。

不要让 diagnostics 变成 Run authority。

---

## 12.5 Recovery Equivalence

对于可比较 crash scenario，最终必须比较：

```text
control run (no crash)
vs
faulted + recovered run
```

至少比较：

```text
exact semantic references
Research Result identity
Artifact logical identity
Candidate evidence
Statistics bindings/results
final Run state
```

运行时 Attempt history 可以不同，因为 crash 本身是 operational history。

正确等价是：

```text
semantic truth same
operational audit accurately records difference
```

不是要求两个 Run 的所有 operational UUID/timestamps byte-identical。

```text

[ ] crash tests do not depend on broad sleeps
[ ] no test-only semantic production path
[ ] lease expiry creates forward recovery, not stale revival
[ ] stale Worker cannot finalize
[ ] ownership uncertainty cannot finalize

[ ] semantic corruption fails closed
```

# 13. P8.6.5 — Coherent Backup / Restore Certification

## 13.1 第一性目标

## 13.2 Restore Pair Invariant

必须保持：

```text

```

并满足：



### 禁止

```text
DB references object X
but restored semantic store lacks/corrupts X
```

这种情况必须 fail closed。

```text

```

## 13.4 正向真实恢复 Scenario

不要把：
