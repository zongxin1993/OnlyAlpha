# 1. First-Principles Goal

P9.K.7 exists because a direct in-process Python call and a remote cross-process/cross-OS call have fundamentally different failure semantics.

Inside one process:

```text
caller → typed Python function → return/exception
```

Across a remote boundary:

```text
OnlyAlpha Kernel
→ network transport
→ remote Gateway process
→ provider / venue
```

the system must explicitly answer:

```text
What is the identity of one logical remote mutation?
What is merely one transport attempt?
What does timeout mean after submission?
How is a retry bound to the original intent?
How are duplicate mutations prevented?
How is command-id reuse with different intent rejected?
How are transport errors separated from application/provider errors?
How is stream ordering determined?
How are duplicates detected?
How are gaps handled?
How does exact resume work?
What happens when retained stream history is insufficient?
How does the Kernel know a Gateway process restarted?
How are protocol compatibility and capabilities negotiated?
How does a future QMT/CTP Gateway remain infrastructure rather than a second Product API?
```

The goal is therefore:

> Freeze and mechanically prove one provider-neutral, deterministic, retry-safe, fail-closed remote infrastructure protocol boundary before real QMT/CTP/Broker work starts.

This task does **not** implement a production Broker.

It establishes the protocol foundation future providers must obey.

## INV-K7-04 — Identity Taxonomy Is Explicit

Semantics:

### `gateway_id`

Stable configured/logical Gateway identity.

### `gateway_instance_id`

One concrete Gateway process lifetime.

A Gateway restart MUST result in a new instance identity.

A successful TCP reconnect is not evidence that the remote process instance is unchanged.

### `command_id`

One logical retryable remote side effect.

It MUST remain stable across an explicit retry of the same logical command.

### `command_fingerprint`

Canonical binding between `command_id` and remote command intent.

### `correlation_id`

One transport attempt / trace identity.

It MAY change on retry.

Therefore:

```text
logical mutation identity != transport attempt identity
```

### `stream_id + sequence`

Authoritative stream ordering identity.





# 11. Stream Ordering and Recovery

`sequence` is the ordering authority.

Wall-clock time MUST NOT be used to repair, sort or infer missing stream order.

Required behavior:

```text
received sequence == expected next
→ accept

received sequence already applied
→ detect duplicate deterministically
→ do not apply twice

received sequence > expected next
→ explicit gap
→ RESYNC_REQUIRED

resume_after = N
and N+1 history exists
→ continue exactly from N+1

exact continuation unavailable
→ RESYNC_REQUIRED

Gateway process instance changes
→ re-handshake / recovery decision
```

Do not silently:

```text
jump to latest
drop missing events
reorder by timestamp
guess continuity
```

The test Gateway may have bounded history.

History truncation that prevents exact continuation MUST become:

```text
RESYNC_REQUIRED
```
