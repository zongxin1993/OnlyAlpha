4. 本任务第一根本问题：
   Migration History 不是 migration set
============================================================

从第一性原理定义：

Migration History 是一条有序历史链。

假设 Repository migrations：

M1
M2
M3
M4

那么合法数据库 applied history 只能是：

[]

[M1]

[M1, M2]

[M1, M2, M3]

[M1, M2, M3, M4]

任何其他组合必须 fail closed。

例如：

[M2]

[M1, M3]

[M2, M3]

[M1, M2, M4]

全部非法。

因此不能继续使用：

repository migrations - applied migrations

这种 set-difference 模型来判断 pending migrations。

Migration 是 ordered history，
不是 unordered membership set。

5. Exact Prefix Invariant
============================================================

正式冻结：

repository_ids =
(M1, M2, ..., Mn)

applied_ids =
(A1, A2, ..., Ak)

合法必须满足：

applied_ids
==
repository_ids[:len(applied_ids)]

并且对于所有已 applied migration：

database checksum
==
repository checksum

只有满足 exact prefix，
Database 才允许：

BEHIND
或
COMPATIBLE。
