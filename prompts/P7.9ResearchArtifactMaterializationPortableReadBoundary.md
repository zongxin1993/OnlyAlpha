# OnlyAlpha P7.9 — Research Artifact Materialization & Portable Read Boundary

你正在实现 OnlyAlpha 的 P7.9。

Repository:
https://github.com/zongxin1993/OnlyAlpha

目标不是“增加几个导出文件”，也不是构造一个通用 Artifact Framework。

P7.9 的根本任务是：

建立 Research execution plane 与未来 Query / API / Web consumption plane 之间第一个稳定、不可变、自包含、可验证的读取边界。

必须从第一性原理出发：

1. Research Result 是 Research composition authority。
2. Statistics Result 是 Statistics rows 的 semantic authority。
3. Research Artifact 只是 Research Result 的确定性派生物化视图。
4. Artifact 可以复制数据，但绝不能成为新的 Research semantic authority。
5. Artifact 发布后必须能够脱离 Research Result Store / Statistics Result Store / Calculation Result Store 独立读取和验证。
6. 不要为了“通用性”“未来扩展”提前建立没有当前需求支撑的抽象。
7. 不要过度设计。
8. 不要为了减少代码重复而破坏清晰的领域边界。

3. AUTHORITY MODEL — MUST NOT BE VIOLATED
============================================================

必须明确保持三个角色不同：

Statistics Result
    = Statistics rows semantic authority

Research Result
    = exact Statistics Result composition authority

Research Artifact
    = derived immutable materialized read view

Research Artifact：

可以：

- 复制 Statistics rows；
- 作为便于查询的数据物化形式；
- 删除；
- 重建；
- 缓存；
- 复制；
- 携带；
- 离线读取；
- 离线验证。

不可以：

- 修改 Statistics semantics；
- 重新计算 Statistics；
- 成为 Statistics Result authority；
- 成为 Research Result authority；
- 修复 Statistics Result；
- 修复 Research Result；
- 从 Artifact 反向写回上游 Store；
- 在与上游 semantic identity 冲突时覆盖 authority；
- 作为 Research execution authority；
- 根据 Store 扫描结果自行决定 Research Result composition。

正确的数据来源必须是：

ResearchResultStore.load_verified(...)
    ↓
Research Result exact references
    ↓
StatisticsResultStore.load_verified(exact reference)
    ↓
Artifact materialization

严禁：

scan Statistics Store
    ↓
guess/group results
    ↓
construct Artifact

Artifact 的 membership 必须完全由 Research Result 决定。

9. STATISTICS.PARQUET
============================================================

Research Result 可以包含多个 Statistics Results。

P7.9 将 Research Result 引用的 Statistics rows 物化为一张 canonical Parquet table。

建议最小 schema：

    statistics_fingerprint
    ts_event_ns
    statistic_value
    sample_count
    status

其中 Statistics Result fingerprint、Statistics Definition / Plan 等元信息应放入 Manifest catalog，而不是在每一行重复。

如果 current implementation 有充分理由需要额外稳定 identity column，可以加入，但必须证明其必要性。

不要加入：

- display name
- factor title
- human label
- theme metadata
- path
- created_at
- runtime_id
- process id

Canonical ordering：

    statistics_fingerprint ASC
    then ts_event_ns ASC

必须验证：

- 每个 Statistics Result rows 自身 canonical；
- timestamps ordering；
- duplicate timestamps；
- row type；
- Decimal precision；
- status/value contract；
- exact row count。

必须使用当前 Statistics Result 的正式 public semantic helpers / contracts。

不要重新实现一套不同的 IC/RankIC row canonicalization。

============================================================
12. ARTIFACT LOGICAL CONTENT IDENTITY
============================================================

Artifact logical identity 与 physical file bytes 必须严格区分。

禁止：

    artifact_content_fingerprint = sha256(parquet bytes)

因为 Parquet bytes 可能受到：

- compression
- writer version
- metadata encoding
- physical layout

影响，而 logical research content 并没有改变。

Artifact content fingerprint 应基于 canonical logical payload。

例如：

    {
        schema_version,
        profile,
        research_result_fingerprint,
        dataset_snapshot_fingerprint,
        canonical statistics catalog
    }

catalog 至少应包含能够唯一证明 logical rows 的：

    statistics_fingerprint
    statistics_result_fingerprint
    result_content_fingerprint
    canonical Statistics Plan
    row_count

由于每个 Statistics result_content_fingerprint 已经由 canonical rows 计算，不需要为了“保险”再设计五层 hash。

避免 identity inflation。

============================================================
13. PHYSICAL BYTE INTEGRITY
============================================================

statistics.parquet 必须另有：

    data_byte_sha256

它只证明 exact physical file 没有损坏。

必须区分：

    artifact_content_fingerprint
        = semantic/logical deterministic identity

    data_byte_sha256
        = exact physical integrity

不同合法 Parquet physical encoding 不应改变 logical Artifact identity。

不要要求不同机器、不同 compression implementation 产生完全相同 Parquet bytes，除非当前 repository 已正式定义此保证。

============================================================
15. MATERIALIZER CONTRACT
============================================================

Materializer 必须从 verified authority 开始。

推荐行为：

    research_result_store.load_verified(...)
        ↓
    verified Research Result
        ↓
    iterate exact canonical Statistics references
        ↓
    statistics_result_store.load_verified(...)
        ↓
    validate exact:
        statistics_fingerprint
        statistics_result_fingerprint
        dataset_snapshot_fingerprint
        Statistics Plan linkage
        row logical identity
        ↓
    canonical combined table
        ↓
    Artifact candidate

不能相信普通 load/read。

必须使用 verified boundary。

Materializer 必须重新确认：

- Research Result reference 与 Statistics Result exact match；
- 所有 Statistics Results 属于同一个 exact Dataset Snapshot；
- Dataset 与 Research Result manifest exact match；
- Statistics fingerprint 可由 Statistics Plan 重新计算；
- Statistics Result content fingerprint 与 rows exact match；
- Statistics Result fingerprint exact match；
- canonical ordering。

如果 upstream authority corrupt：

    fail closed

不要：

    skip bad member
    partial artifact
    warning and continue

P7.9 V1 Artifact 要么完整，要么不存在。

============================================================
16. STORE MUST NOT DEPEND ON UPSTREAM STORES
============================================================

这是 P7.9 的核心验收条件之一。

Materialization 阶段允许依赖：

    ResearchResultStore
    StatisticsResultStore

但是：

    ResearchArtifactStore.load_verified()

不得访问：

    ResearchResultStore
    StatisticsResultStore
    CalculationResultStore
    DatasetStore

Artifact Store constructor 也不应要求这些 Store。

它可以依赖现有 public semantic model / fingerprint helper 的代码，但不得依赖 upstream persisted authority 才能读取一个已经发布的 Artifact。

也就是说：

    generation = upstream-aware

    published artifact read/verification = self-contained

============================================================
17. SELF-CONTAINED VERIFICATION
============================================================

ArtifactStore.load_verified() 至少验证：

Filesystem contract:

- target exists and is directory
- target/root is not symlink
- manifest is not symlink
- parquet is not symlink
- exact expected file set
- no unexpected nested files
- no partial manifest
- no hidden alternate authority

Manifest contract:

- JSON object
- exact fields
- schema/profile supported
- valid hashes
- valid UTC timestamp
- canonical Statistics catalog order
- no duplicate Statistics fingerprints

Parquet contract:

- file exists
- physical SHA256 exact match
- exact Arrow schema
- exact row count
- canonical row ordering
- no duplicate `(statistics_fingerprint, ts_event_ns)`

Per Statistics group:

manifest Plan
    ↓
recompute statistics_fingerprint
    ↓
group rows
    ↓
recompute result_content_fingerprint
    ↓
recompute statistics_result_fingerprint
    ↓
exact manifest match

Research Result linkage:

canonical Statistics fingerprints
    ↓
reconstruct/verify Research Result Plan identity
    ↓

canonical pairs:
    statistics_fingerprint
    statistics_result_fingerprint
    ↓
recompute Research Result content identity
    ↓
recompute Research Result fingerprint
    ↓
exact manifest match

最后：

recompute artifact_content_fingerprint
    ↓
exact manifest match

因此，一个合法 Artifact 必须能够在 upstream Stores 完全不可用时通过 load_verified()。

============================================================
18. SELF-CONTAINED DOES NOT MEAN NEW AUTHORITY
============================================================

必须在 ADR 和 code semantics 中明确：

Artifact self-verifiable

不等于：

Artifact becomes Research authority

Artifact 能证明的是：

    “这些物化数据与 Artifact 声明的 immutable upstream identities 一致。”

它不能证明：

    “Artifact 可以替代 upstream Store 执行 Research。”

禁止实现：

    Artifact → restore Statistics Store
    Artifact → rebuild Research Result Store
    Artifact → import authority

这类功能属于未来独立设计。

============================================================

沿用 OnlyAlpha 已成熟的 immutable store 原则。

目标：

    ↓
unique staging directory
    ↓
write statistics.parquet
    ↓
physical read-back
    ↓

============================================================
20. RE-ENTRY / RECOVERY SEMANTICS
============================================================

Artifact 是 deterministic derived output。

不需要：

- DB checkpoint
- lease
- journal
- worker state
- retry table

Recovery model：

Case A:

crash before publication

    stage is non-authoritative
    next run rematerializes

Case B:

publication completed
process crashed before caller received result

    retry
        ↓
    load existing verified Artifact
        ↓
    same logical content
        ↓
    REUSED

Case C:

two concurrent equivalent publishers

    both stage
        ↓
    one atomic publish succeeds
        ↓
    loser observes existing Artifact
        ↓
    load_verified
        ↓
    same content
        ↓
    REUSED

Case D:

same logical target
different artifact_content_fingerprint

    DETERMINISTIC_ARTIFACT_CONFLICT

Case E:

existing target corrupt

    ARTIFACT_CORRUPT

绝不能：

    corrupt
    → treat as missing
    → delete
    → silently rebuild

============================================================
22. ERROR CONTRACT
============================================================

建立稳定、fail-closed 的 Research Artifact errors。

至少需要能够区分类似：

    ARTIFACT_NOT_FOUND
    ARTIFACT_INVALID
    ARTIFACT_CORRUPT
    ARTIFACT_COMMIT_FAILED
    DETERMINISTIC_ARTIFACT_CONFLICT

命名应遵守当前 OnlyAlpha Research error conventions。

重点：

NOT_FOUND != CORRUPT

INVALID
    = input/materialization contract invalid

CORRUPT
    = published persisted artifact 无法通过完整 verification

COMMIT_FAILED
    = publication process failure

DETERMINISTIC_ARTIFACT_CONFLICT
    = same logical address produced different logical content

不要把所有异常变成一个 RuntimeError 字符串。

同时不要设计复杂的 error hierarchy。

稳定 error code + 清晰根因即可。

27. TEST DESIGN
============================================================

测试必须优先验证 contract，而不是追求数量。

至少覆盖：

1. Exact composition

Research Result references A/B
→ Artifact 只能包含 A/B

2. Ordering independence

upstream enumeration ordering changes
→ same canonical Artifact

3. Created time neutrality

different created_at
→ same logical artifact_content_fingerprint

4. Physical path neutrality

different roots
→ same logical artifact_content_fingerprint

5. Self-contained verification

upstream Stores unavailable
→ valid Artifact still loads

6. Byte corruption

modify parquet bytes
→ ARTIFACT_CORRUPT

7. Semantic corruption

change rows while maintaining parseable parquet
→ logical fingerprint verification fails

8. Manifest corruption

change Statistics Result fingerprint
→ ARTIFACT_CORRUPT

9. Plan corruption

change Statistics Plan metadata
→ recomputed Statistics fingerprint mismatch

10. Research composition corruption

remove/reorder/duplicate catalog member
→ fail closed

11. Dataset mismatch

→ fail closed

12. Unexpected file

→ fail closed

13. Symlink

→ fail closed

14. Re-entry

same semantic candidate
→ existing verified Artifact reused

15. Deterministic conflict

same logical target
different semantic materialization
→ DETERMINISTIC_ARTIFACT_CONFLICT

16. Publication race

winner publishes
loser verifies existing
→ reuse if semantically identical

17. Failed staging

→ no authoritative target remains

不要写依赖 sleep / timing luck 的 race test。

使用 deterministic injection / monkeypatch / controlled publication failure。
