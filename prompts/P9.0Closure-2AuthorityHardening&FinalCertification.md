# 2. First-Principles Invariants

## 2.1 Historical facts are immutable

If a Research Result was produced by Research Implementation `R1`, future code must still prove:

```text
Result X ← R1
```

It must never silently become:

```text
Result X ← current Registry implementation R2
```

Historical execution provenance is a fact. Current Registry state is not historical evidence.

## 2.2 Semantic result != execution provenance

Keep these authorities separate:

```text
Calculation Result
→ what was calculated

Research Calculation Execution Evidence
→ which exact implementation produced it
```

Do not pollute Calculation semantic identity with execution-environment metadata.

The same semantic result may be reproduced by more than one implementation:

```text
R1 → Result Y
R2 → Result Y
```

Then:

```text
Calculation Result identity = same
Execution Evidence identity = different
```

## 2.3 Evidence can only be produced by its authority

No caller may submit a precomputed hash/output and claim equivalence.

Production Equivalence Evidence must be produced only by a trusted Certification Authority that:

```text
resolves exact RESEARCH implementation
resolves exact TRADING implementation
materializes required canonical certification profile/corpus
executes both exact backends
compares exact outputs
publishes immutable evidence
```

## 2.4 StrategyRevision construction != executable Strategy publication

`OnlyStrategyRevision(...)` may remain a valid Domain Value constructor.

But raw Revision must not be directly publishable to the executable Strategy Store.

Only verified Freeze may publish a Strategy into the runtime-readable authority.

## 2.5 Runtime is read-only

Backtest, SIM and future LIVE must only receive a Strategy reader capability.

They must not hold writer/publisher/raw commit capability.

## 2.6 Fail closed

Unknown provenance, missing evidence, unverified legacy data, missing exact implementation identity, missing certification profile, incompatible evidence, or unauthorized publication must fail closed.

Never guess, auto-adopt, auto-upgrade old evidence, substitute current implementation for historical implementation, or fall back to legacy store semantics.

# 6. C2.1 — Exact Research Implementation Resolution

## Goal

Ensure the Research execution path knows the exact implementation before execution begins.

Do not resolve a backend, execute it, and later guess which implementation was used.

## 6.1 Resolved backend contract

Introduce or extend a type equivalent to:

```python
@dataclass(frozen=True, slots=True)
class OnlyResolvedResearchCalculationBackend:
    provider: OnlyResearchCalculationBackend
    implementation_manifest: OnlyCalculationImplementationManifest
```

The Research backend resolver must resolve:

```text
semantic Calculation reference
+
RESEARCH backend
→ exact provider
+
exact implementation manifest
```

Missing implementation manifest must fail closed.

## 6.2 Build execution plan before processing data

Prefer:

```text
Graph
↓
resolve all node RESEARCH implementations
↓
freeze Research Calculation Execution Plan
↓
execute data
```

Conceptual model:

```text
OnlyResearchCalculationExecutionPlan

Graph fingerprint
bindings:
  node fingerprint
  provider
  exact implementation manifest
```

The purpose is to prevent execution from being reinterpreted while running.

## 6.3 Per-node resolution

Each Graph node must resolve exactly once for the execution plan.

Do not re-resolve per instrument or per row.

## 6.4 Execution output

Extend `OnlyResearchCalculationExecution` or create a companion provenance value so execution carries:

```text
research_implementation_bindings:
  node_fingerprint
  research_implementation_fingerprint
```

Bindings must be canonical, unique, and exactly cover Graph nodes.

## C2.1 Acceptance

Tests must prove:

```text
same Graph + same exact Registry
→ same Research implementation binding set

implementation resource bytes change
→ implementation fingerprint changes

semantic dependency changes
→ implementation fingerprint changes

missing implementation manifest
→ execution path fails closed

Graph node set != implementation binding set
→ rejected
```

```text

   Evidence Result == verified Calculation Result

4. Verify implementation manifest, state capability and checkpoint schema.

   N + R1 + T1 + required Certification Profile.

6. Construct StrategyImplementationBinding:
   N, R1, T1.
```

Delete the behavior:

```text
Trading Admission
→ Registry.resolve(RESEARCH)
→ assume current Research implementation is historical implementation
```
