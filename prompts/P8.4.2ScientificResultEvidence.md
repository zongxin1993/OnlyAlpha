# 2. 第一性原理

所有实现必须从以下事实出发。

---

## 2.1 一个事实只能有一个 authority

必须保持：

```text
Dataset Snapshot
→ exact market truth

Calculation Result
→ exact Calculation / Signal value truth

Statistics Result
→ exact admitted statistics truth

Research Result
→ exact Research composition / membership / lineage truth

Research Artifact
→ derived immutable portable read projection

Research Query
→ deterministic read-only projection

Browser
→ presentation only
```

严格禁止增加：

```text
ScientificEvidenceStore
CandidateStore
SignalStore
GraphStore
PredicateResultStore
```

因为这些都会与现有 authority 竞争同一事实。

---

## 2.2 Specification 表达“请求什么”

Specification 不是 Result。

Specification 应回答：

```text
执行什么？
发布哪些 scientific evidence？
哪个 candidate space 属于本 Research？
哪些 exact signal roles 应成为 evidence？
```

它不保存执行结果。

---

## 2.3 Result Plan 表达“应该由什么组成”

Result Plan 必须成为 deterministic composition plan：

```text
exact Dataset
exact Calculation members
exact Candidate lineage
exact Published Series members
exact Signal members
exact Statistics members
```

它不保存数据行。

---

## 2.4 Research Result 表达“实际引用了什么”

Research Result 只保存 verified immutable upstream references。

禁止把大量 Calculation values 复制进 Research Result JSON。

---

## 2.5 Artifact 是投影，不是第二个科学事实 authority

Artifact 可以复制数据，使其：

```text
portable
self-contained
queryable
Web-friendly
```

但 Artifact 不能：

```text
重新计算 Signal
重新计算 Statistics
重新生成 Candidate
扫描 stores 猜 membership
```

# 5. P8.4.2-A — Specification V2 Evidence Contract

这是整个 P8.4.2 最关键的阶段。

---

## 5.1 Specification V2 的目标

当前 Specification V1 主要表达：

```text
Dataset
Calculations
Statistics
```

V2 应表达：

```text
Execution Specification
+
Scientific Evidence Declaration
```

概念结构：

```text
OnlyResearchSpecification V2
│
├── dataset_snapshot_fingerprint
├── calculations[]
├── statistics[]
│
└── evidence
    ├── candidate_calculation_id
    ├── published_series[]
    └── signals
        ├── eligibility?
        ├── entry?
        └── exit?
```

Evidence 只声明 membership。

禁止放：

```text
calculation result values
statistics values
artifact paths
byte hashes
created_at
```

# 6. 尽量复用现有 `OnlyResearchSeriesSelector`

当前如果已有：

```python
OnlyResearchSeriesSelector(
    calculation_id,
    template_node_id,
    output_name,
)
```

优先直接复用。

不要为了 Scientific Evidence 再创建功能重复的：

```text
EvidenceSeriesSelector
PublishedSeriesReference
ScientificSeriesSelector
```

除非现有类型在语义上确实无法承担此职责，并且可以明确证明新增类型解决了真实歧义。

---

# 7. 推荐最小 Evidence 类型

优先考虑类似：

```python
@dataclass(frozen=True, slots=True)
class OnlyResearchSignalEvidenceSpec:
    eligibility: OnlyResearchSeriesSelector | None
    entry: OnlyResearchSeriesSelector | None
    exit: OnlyResearchSeriesSelector | None


@dataclass(frozen=True, slots=True)
class OnlyResearchScientificEvidenceSpec:
    candidate_calculation_id: str
    published_series: tuple[OnlyResearchSeriesSelector, ...]
    signals: OnlyResearchSignalEvidenceSpec
```

名字可根据仓库现有命名调整。

不要机械照搬名称。

判断标准是：

```text
是否真实表达了唯一职责？
是否减少了歧义？
是否避免重复 authority？
```

---

# 8. `candidate_calculation_id`

必须明确哪个 Calculation 的 candidate space 是 Research product candidate space。

不要靠：

```text
第一个 Calculation
唯一 Sweep Calculation
名字前缀猜测
Graph 类型猜测
```

Specification 应显式持有：

```text
candidate_calculation_id
```

它只是 exact composition reference，不是新 authority。

---

# 9. Published Series Membership

Definition 已经有：

```text
published_outputs
```

架构不变量：

```text
只有 explicitly published outputs
才能进入 Scientific Artifact / Query product evidence。
```

因此 Definition Resolver 必须：

```text
Definition-local logical output
        ↓
Specification selector
```

例如：

```text
rsi.value
```

resolution 后进入类似：

```text
calculation_id = "decision"
template_node_id = "rsi"
output_name = "value"
```

浏览器不应该 author：

```text
node_fingerprint
calculation_fingerprint
```

这些必须由 server resolver 产生。

---

# 10. Target 也是 Scientific Variable

明确发布的 Target output 也应进入：

```text
published_series
```

不要把 Target 另建一个独立 Evidence Registry。

Series membership 可以包含：

```text
Indicator Feature
Factor Score/output
Target
```

Signal 由于有额外 role semantics，单独由 `signals` 声明即可。

terminal semantic role，则 Specification Evidence 直接引用对应 terminal selector。

不要：

```text

```

```text

```

三个独立事实。

# 12. Candidate Identity Closure

当前 Candidate identity 如果依赖：

```text
resolved_definition_fingerprint
```

但 Fresh Worker 只持久化：

```text
Specification
```

则 Candidate identity 无法从 Run alone 重建。

这必须在 P8.4.2-A 关闭。

推荐目标：

```text
CandidateFingerprint =
HASH(
    schema_version,
    specification_fingerprint,
    candidate_calculation_id,
    canonical_assignment,
    calculation_fingerprint
)
```

但不要盲目照抄公式。

开始实现前必须验证当前：

```text
Calculation fingerprint
Specification fingerprint
assignment
```

各自已经包含哪些事实。

原则：

```text
同一个事实不要重复进入 identity payload
```

---

# 13. Candidate Identity 的意义

必须明确区分：

```text
Calculation identity
```

和：

```text
Research Candidate identity
```

Calculation Fingerprint 回答：

```text
这个 exact Dataset + Graph execution 是什么？
```

Candidate Fingerprint 回答：

```text
这个 exact Research Specification 中，
这个 candidate 是谁？
```

因此：

```text
execution identity
!=
research product identity
```

但二者必须有 exact linkage。

---

# 14. Publication Intent 必须进入 Specification identity

假设两个 Definition：

```text
A:
publish momentum.score

B:
publish momentum.score
publish momentum.raw
```

即使执行 Graph 一样：

```text
CalculationFingerprint A
==
CalculationFingerprint B
```

Scientific Research intent 仍然不同。

因此 V2 必须做到：

```text
SpecificationFingerprint A
!=
SpecificationFingerprint B
```

这允许：

```text
Calculation Result 复用
```

同时保持：

```text
Research product identity 不错误折叠
```

---

# 15. Candidate Identity 必须只有一个构造入口

如果新增 Candidate identity helper：

```python
only_research_candidate_fingerprint(...)
```

必须成为唯一构造入口。

禁止：

```text
Definition Resolver 写一套 hash payload

Specification Resolver 再写一套

Artifact verifier 再写第三套
```

所有调用方必须复用同一 helper。

---

# 16. Specification V1 Backward Compatibility

不要修改已有 V1 fingerprint semantics。

如果选择一个模型支持 schema V1/V2：

必须做到：

```text
V1:
canonical payload 与现状完全一致

V2:
明确包含 evidence
```

V1 不应被自动升级后重新 fingerprint。

禁止：

```text
读取旧 V1
→ silently convert V2
→ identity 改变
```

---

# 17. Run / PostgreSQL 不增加 Evidence Authority

当前 Run 已经保存：

```text
specification_schema_version
specification_fingerprint
canonical_specification_payload
```

优先直接让 Specification V2 穿过现有 Run persistence。

不要增加：

```text
run_evidence_json
scientific_evidence table
candidate table
signal table
```

除非当前 PostgreSQL schema 事实证明无法保存 V2 canonical Specification。

正常情况下：

```text
Specification V2
→ Run
→ PostgreSQL canonical payload
→ Fresh Worker
```

已经足够。

# 18. Fresh-process Determinism Gate

这是 P8.4.2-A 必须新增的正式测试。

当前 internal PREDICATE registration 可能由 Definition Resolver 构造过程触发。

但真实产品链是：

```text
API Process
→ writes exact Specification

Worker Process
→ reloads exact Specification
→ re-resolves
→ creates Engine Runtime
```

不能依赖：

```text
API process 曾经在同一个 Python registry 中注册过 Predicate
```

必须测试：

```text
Registry A
→ Definition Resolver
→ Specification containing internal Predicate

serialize Specification

discard Registry A

Registry B
→ Specification Resolver
→ resolve

Engine / Runtime Registry C
→ execute exact workload
```

要求：

```text
same semantic resolution
same Candidate identity
successful execution
```

---

Research Calculation composition

# 76. 最终核心原则

整个 P8.4.2 始终用这五条判断每一个改动：

```text
1. Specification owns requested scientific evidence membership.

2. Research Result owns exact composition/reference truth,
   not upstream data rows.

3. Artifact is a derived disposable portable projection,
   never a second scientific authority.

4. Candidate identity must be reconstructible
   from persisted exact Specification alone.

5. No downstream layer may infer unpublished evidence
   by scanning or guessing from upstream stores.
```

如果一个改动无法回答：

```text
它解决了哪个真实的信息丢失？
它消除了哪个真实歧义？
它维护了哪个唯一 authority？
它保证了哪个 deterministic invariant？
```

就不要做。

最终目标不是：

```text
更多模型
更多表
更多服务
更多接口
```

最终目标是：

```text
Definition 中已经确定的科学意图
经过 durable Run 和 fresh Worker
最终仍然形成同一份
可验证、可复现、可移植、不可猜测的科学证据。
```
