# 1. 你的角色与唯一目标

你正在实现 OnlyAlpha 的 **P7.5**。

P7.5 的正式目标是：

> **在不创建第二套 Dataset / Calculation / Result / Job authority、不激活 Research Runtime、不引入 Scheduler/Worker/Job DB 的前提下，建立 Indicator → Feature → Raw Factor Value → Factor Score 的正式语义体系，并让真实 Factor 与 Cross-Section Scoring 完整进入现有 Calculation Graph、Research deterministic execution、immutable Calculation Result 与 P7.4 Research Job。**

P7.5 不是“添加几个因子”的功能开发。

P7.5 是一次 **semantic closure + execution model closure**：它必须证明 P7.0 建立的 Calculation abstraction 真正高于 Indicator abstraction，能够可靠承载 Factor Research，而不是仅仅把 Indicator 换了一个名字。

```text

                     ↓

                     ↓
```

不要为了结构对称扩展范围。

# 4. P7.5 必须冻结的概念模型

P7.5 必须以以下概念关系为设计基础：

```text
                      Calculation
                           │
             ┌─────────────┴─────────────┐
             │                           │
         Indicator                     Factor
             │                           │
      named typed outputs          research semantics
             │                           │
           Feature                  Factor Value
                                         │
                              Ranking / Normalization
                                         │
                                  Factor Score
                                      [0,1]
```

未来可进一步组合：

```text
Factor A Value → Scoring → Factor A Score ─┐
                                           │
Factor B Value → Scoring → Factor B Score ─┼→ Composite Score
                                           │
Factor C Value → Scoring → Factor C Score ─┘
```

本阶段必须遵守下面的语义边界。

## 4.1 Calculation 是统一工程抽象

Indicator、Factor、Scoring calculation 必须继续复用现有 Calculation 基础设施：

```text
type_id
semantic_version
parameters
inputs
input bindings
outputs
warmup
missing-value semantics
timestamp semantics
numeric semantics
canonical graph
semantic fingerprint
backend registry
Research execution
Calculation Result
Research Job
```

禁止创建：

```text
FactorGraph
FactorRegistry
FactorJob
FactorResultStore
ScoreResultStore
FeatureJob
FeatureStore
```

除非 current repository 中已经存在不可替代的正式 authority，且有当前 ADR 明确要求；否则这是重复 authority。

## 4.2 Indicator

Indicator 是确定性数学/统计变换：

```text
named typed inputs
        ↓
deterministic algorithm
        ↓
named typed outputs
```

运行时可以使用 `Mapping[str, ArrowArray]` 等 mapping-like interface，但它只是数据 transport。

**Definition/schema 才是 authority。**

禁止退化成 `dict[str, Any] -> dict[str, Any]` 弱 contract。

## 4.3 Feature

Feature 是“可供后续 Research / ML / Factor 消费的数据语义”，不是新执行产品。

Feature 应优先表达为现有 Calculation output port：

```text
(node_fingerprint, output_name)
```

或等价的现有 canonical reference。

不要新增 Feature executor/store/job/fingerprint。

## 4.4 Factor

Factor 表示带有研究假设的 Calculation。

Factor 可以依赖：

- 一个或多个 Indicator output；
- 其他明确 Calculation output；
- 合法 Dataset source；
- 在 DAG 中显式声明的其他 Factor output。

Factor backend **不得隐藏执行 Indicator**。

错误示例：

```python
class MomentumFactor:
    def execute(...):
        # 内部偷偷重新算 rolling return / EMA / RSI
        ...
```

正确结构：

```text
RollingReturn20 ──┐
                  ├→ MomentumFactor
RollingReturn60 ──┘
```

所有依赖必须在 canonical Calculation Graph 中显式可见，使 identity、introspection、debug、reuse 和测试都能看到真实结构。

## 4.5 Raw Factor Value

Factor 的首要输出是 **Raw Factor Value**，不强制映射到 `[0,1]`。

示例：

```text
Momentum = +0.137
Value = 8.4
Quality = -1.27
Volatility = 0.021
```

Raw Factor Value 必须保留原始研究信息，因为未来 Statistics、IC、Rank IC、ML、winsorization、normalization 可能需要不同处理。

## 4.6 Factor Score

Factor Score 是 Factor Value 经确定性 scoring / ranking / normalization 后得到的标准化比较值。

冻结：

```text
Factor Score ∈ [0,1]
```

0 与 1 都是合法端点。

**Factor Value != Factor Score。**

该区别必须能够通过 machine-readable Calculation contract 被识别，不能只存在于类名或文档里。

建议优先通过现有 input/output `semantic_type` 建立稳定语义，例如：

```text
FACTOR_VALUE
FACTOR_SCORE
```

如果 current repository 已有更正式的 semantic-type authority，复用它。

不要为了这一点修改所有既有 Indicator definition 的 semantic identity。

## 4.7 Scorer 的工程表示

概念上 Scorer 与 Raw Factor 是不同语义：

```text
Factor Value → Scorer → Factor Score
```

但**不要机械地因为概念不同就新增 `OnlyCalculationKind.SCORER`**。

默认优先方案是：

- 保持现有 Calculation family/Registry 架构；
- 用 exact port semantic (`FACTOR_VALUE` / `FACTOR_SCORE`)；
- 用现有或最小扩展的 execution-shape semantic；
- 让 scoring algorithm 仍然是一个 canonical Calculation node。

只有当重新阅读 current repository 后能证明：

1. 现有 `INDICATOR / FACTOR` kind 无法诚实表达 Scorer；
2. 不增加 `SCORER` 会造成语义歧义或 architecture leak；
3. 新增 kind 不会改变任何既有 Indicator/Factor fingerprint；
4. 新增 kind 不需要破坏 P7.0–P7.4 Registry/result/reuse contracts；

才允许增加 `OnlyCalculationKind.SCORER`。

若做此决定，必须在 P7.5 ADR 中写出 rejected alternatives 和 identity impact analysis。

**非协商要求是 Scorer 语义必须和 Raw Factor Value 区分；是否需要新的 enum 不是预设答案。**

## 4.8 Direction 属于 scoring semantics

不要把 `HIGHER_IS_BETTER / LOWER_IS_BETTER` 固定成 Raw Factor 的永久属性。

同一个 Raw Factor 可能在不同模型中被不同方向解释。

优先将 direction 作为 Scorer 的 exact semantic parameter：

```text
HIGHER_IS_BETTER
LOWER_IS_BETTER
```

它必须进入 scorer node semantic identity。

# 5. P7.5 目标纵切面

实现至少一个真实 Raw Factor 和一个真实 Cross-Section Scorer。

## 5.1 Raw Momentum Factor

优先使用当前官方 Indicator plugin 已存在并支持 RESEARCH backend 的 Rolling Return definition。

不要猜 type_id、semantic_version、output name；从当前 Registry/plugin source 中读取真实 contract。

构造类似：

```text
Rolling Return(short_window) ──┐
                               ├→ Momentum Factor
Rolling Return(long_window) ───┘
```

Momentum Factor 必须：

- 为真实 `FACTOR` semantic；
- 推荐为 `TIME_SERIES` Factor；
- 输入来自两个显式 upstream node output；
- 输出为 `FACTOR_VALUE` semantic；
- 使用 Decimal；
- 不使用 float64 作为 semantic authority；
- 参数必须通过现有 typed parameter schema normalized；
- backend 只计算自己声明的 Factor 公式，不重新计算 upstream Indicator。

一个可接受的最小公式：

```text
momentum = short_weight * return_short + long_weight * return_long
```

`short_weight` / `long_weight` 为 exact Decimal semantic parameters。

不要求权重之和为 1，除非你能证明这是 Factor 定义本身不可缺少的 invariant；不要引入没有研究必要性的 cross-field validation。

若当前 port semantic compatibility 不允许直接将 Rolling Return output 接入 Factor：

- 先分析原因；
- 不要为了 P7.5 随意修改既有 Indicator semantic_type，从而改变旧 fingerprints；
- 优先采用兼容且不改变历史 identity 的最小方案；
- 如果确实必须变更既有 semantic contract，则这是重大 identity migration，必须停止并报告，而不是偷偷实施。

## 5.2 Cross-Section Percentile Scorer

实现一个正式、确定性的 Cross-Section Percentile Scorer，用于：

```text
FACTOR_VALUE
    ↓
Cross-Section Percentile Scorer
    ↓
FACTOR_SCORE [0,1]
```

其 v1 行为必须 exact、可测试、无库默认值依赖。

建议冻结以下 v1 语义：

### Input

- exact upstream `FACTOR_VALUE`；
- Decimal；
- cross section 以 exact `ts_event_ns` 形成；
- instrument identity 来自 executor 的 canonical axis，不让 backend 从无序容器自行推断。

### Canonical ordering

同一 timestamp 内 instrument 必须按稳定 identity 排序，例如：

```text
sorted(instrument_id)
```

禁止依赖：

- provider order；
- Parquet physical order；
- filesystem order；
- Python dict insertion order；
- worker/process completion order。

### Missing / warmup

对于 v1：

- upstream row 存在但 Factor Value 为 null：该 instrument 在该 timestamp 的 score 输出为 null；
- 非 null instruments 形成 eligible scoring set；
- 不 forward-fill；
- 不 backward-fill；
- 不 silent drop 后丢失原 instrument 对应关系；
- 不用 0 替代 null；
- exact missing policy 必须由 Definition + backend behavior 一致表达。

如果某 declared upstream input 在 exact `(timestamp, instrument)` key 上根本缺失，必须遵守当前 Graph/input contract，默认 fail closed；不要隐式 outer-join + fill。

### Tie semantics

v1 使用显式 **average rank**，不要调用某个第三方库默认 `rank()` 后假设语义稳定。

### Score formula

对一个 timestamp 的非 null eligible values：

```text
N = eligible instrument count
```

若：

```text
N == 0
```

则该 timestamp 无有效 score；所有对应 null input 保持 null。

若：

```text
N == 1
```

唯一 eligible instrument 的 score 固定为：

```text
0.5
```

若：

```text
N >= 2
```

以 value ascending 的 average zero-based rank：

```text
base_score = average_rank / (N - 1)
```

若：

```text
direction = HIGHER_IS_BETTER
```

则：

```text
score = base_score
```

若：

```text
direction = LOWER_IS_BETTER
```

则：

```text
score = 1 - base_score
```

Score 必须满足：

```text
0 <= score <= 1
```

所有数学使用 Decimal，并通过 Definition 冻结 precision / quantum / rounding；禁止由 Python float 或 Arrow float64 决定 canonical result。

如果 current numeric contract 已有更严格规则，服从当前 contract 并在 ADR 中记录实际公式。

目标是：给定一个 Calculation type/definition，程序、人、CLI、未来 UI、ML 或 Agent 能稳定读取：

```text
kind / semantic role
type_id
semantic_version
parameters
parameter types/defaults/min/max/enums
inputs
input data types
input dimensions
input semantic types
outputs
output data types
output dimensions
output semantic types
warmup
missing-value semantics
```

- 输出顺序必须 deterministic。

# 7. Research Calculation Executor：从 instrument-first 升级为 semantic-node-first

这是 P7.5 最重要的执行层工作。

当前 baseline 的核心执行形态是：

```text
for instrument:
    for graph node:
        execute
```

这隐含“每个 node 都 instrument-isolated”，适合 Indicator，但不能支持真正 cross-section calculation。

P7.5 必须把内部 execution workspace 调整为：

```text
for node in graph.ordered_nodes:

    if node is TIME_SERIES execution shape:
        execute deterministically by instrument

    if node is CROSS_SECTION execution shape:
        execute deterministically by timestamp across instruments
```

核心原则：

```text
Graph 决定 dependency/topology
Definition 决定 semantic execution shape
Executor 只执行，不发明业务语义
```

## 7.1 不创建第二套 DAG

继续使用：

```text
OnlyCalculationGraphDefinition
```

作为唯一 dependency / cycle / port compatibility / canonical node ordering authority。

禁止新增：

```text
FactorGraph
ResearchFactorGraph
ScorerGraph
CrossSectionGraph
```

## 7.2 TIME_SERIES execution

所有既有 Indicator 行为必须保持不变：

- instrument-isolated；
- instrument stable order；
- row canonical event-time order；
- existing warmup/missing/timestamp/numeric semantics；
- existing backend resolution；
- existing output validation。

Raw Momentum Factor 也应沿用该 execution shape。

## 7.3 CROSS_SECTION execution

Cross-section node 必须按 exact timestamp 组织同一个 upstream semantic plane。

建议内部 workspace 以明确 key 管理：

```text
(node_fingerprint, instrument_id, ts_event_ns)
```

或等价的结构化 immutable/canonical representation。

不要把全局状态塞进 backend。

backend 应只得到已经 canonicalized 的 named typed arrays；instrument/timestamp alignment authority 属于 executor。

尽量复用现有 Research backend SPI：

```text
execute(definition, inputs)
```

如果同一 narrow SPI 能诚实处理“时间序列向量”和“横截面向量”，不要因为 axis 不同就创建第二套 backend registry。

只有现有 SPI 无法表达必要语义时才做最小扩展，并写 ADR。

## 7.4 Input alignment

Cross-section node 的 upstream inputs 必须按 exact semantic keys 对齐。

禁止：

- implicit forward fill；
- implicit nearest timestamp；
- float cast；
- silently dropping duplicate rows；
- silent intersection that hides required input absence；
- physical row order 作为 alignment authority。

重复 `(instrument_id, ts_event_ns)`、非 canonical timestamp、声明 input 缺失等应使用现有稳定 error family fail closed；若必须新增 error code，保持 phase-aware、稳定、精确。

## 7.5 Final output representation

**execution shape 不等于 durable storage shape。**

即使 Cross-Section Scorer 在执行时按 timestamp × instruments 计算，最终应优先重新 canonicalize 回当前 P7.2/P7.3 可消费的 node/instrument output：

```text
node
 ├── instrument A
 ├── instrument B
 ├── instrument C
 └── instrument D
```

原则上不要修改 P7.3 的：

```text
calculation_fingerprint primary key
Calculation Result fingerprint
(node_fingerprint, instrument_id) partition identity
manifest authority
verified read
atomic publish
conflict semantics
```

如果现有 Result Store 无法容纳合法 cross-section output，先证明具体不变量冲突，再做最小修改。

**不得因为 execution order 从 instrument-first 改为 node-first，而改变既有 Indicator-only graph 的 observable result identity。**

必须加入 golden/regression tests 证明旧 Indicator Calculation Graph 的：

- graph fingerprint；
- calculation fingerprint；
- logical result；
- calculation result fingerprint（如果当前 reference 已冻结）；

保持不变。

# 8. P7.3 / P7.4 必须继续作为唯一 Result / Job authority

P7.5 不创建：

```text
FactorResult
FactorResultStore
ScoreStore
FactorJob
ScorerJob
FeatureJob
```

Raw Factor Value 和 Factor Score 都是 Calculation Graph node outputs。

它们的 durable authority 继续是 P7.3 Calculation Result Store。

Research Job 继续由 P7.4 orchestrator 负责：

```text
Plan
  ↓
load_verified(calculation_fingerprint)
  ├── valid → REUSED
  └── RESULT_NOT_FOUND → deterministic execute → immutable commit → EXECUTED
```

P7.5 不得引入：

- `exists()` 作为 reuse authority；
- corrupt result 自动删除；
- corrupt result 自动重算；
- overwrite；
- mutable calculation cache；
- Job DB；
- lease；
- global lock。

必须验证完整 Factor/Scorer Graph：

```text
first invocation  → EXECUTED
second invocation → REUSED
```

第二次调用不能再次执行 factor/scorer backend。

若 durable result 被破坏：

```text
load_verified() must fail closed
```

不能以重新计算掩盖 corruption。

# 9. 官方 plugin ownership

Core owns contracts；plugin owns concrete algorithms。

P7.5 后官方 Factor plugin 不应继续为空。

至少提供：

1. 一个真实 Raw Momentum Factor RESEARCH backend；
2. 一个真实 Cross-Section Percentile Scoring calculation RESEARCH backend。

优先放在当前官方 Factor plugin 中，除非 current workspace/plugin conventions 明确证明新增独立 scorer plugin 更干净且不会扩大 scope。

无论放在哪里：

- Core 不得反向 import concrete plugin；
- concrete algorithm 不得放进 `src/onlyalpha/calculation` Core；
- plugin registration 必须通过现有 discovery/Registry；
- exact `type_id + semantic_version + backend`；
- unknown type/version/backend 必须 fail closed；
- 不提供 “latest version” fallback；
- 不提供 TRADING backend fallback。

不要为了 P7.5 强行给新 Factor 实现 TRADING backend。

如果只有真实 RESEARCH backend，就只声明 RESEARCH availability。

# 11. Identity 保护规则

P7.5 最重要的非功能要求之一是：**不能破坏 P7.0–P7.4 已建立 identity。**

必须遵守：

1. 不创建无必要的新 Factor/Feature/Score fingerprint。
2. Dataset identity 保持不变。
3. Calculation identity 仍由现有 canonical inputs 决定。
4. Factor/Scorer node identity 由其 canonical Calculation Definition 自然产生。
5. Factor Score direction、tie method、numeric semantics 等真正改变结果的参数必须进入 node semantic identity。
6. physical path、process、worker、runtime、wall clock、UUID 不进入 semantic identity。
7. 不因为新增 P7.5 capability 改变所有旧 Definition 的 schema_version/fingerprint。
8. 如果考虑修改 Calculation Definition schema：先做 identity blast-radius analysis。除非无法避免，否则拒绝全局 schema bump。
9. 不修改既有 official Indicator semantic versions 来适配 P7.5；行为变化必须新 semantic version。

特别注意：

如果添加新的 enum value、可选字段或 semantic type，必须证明 existing serialized definitions round-trip、fingerprints、golden references 不变。

# 13. 必须覆盖的测试矩阵

P7.5 的测试重点不是“公式算对一次”，而是冻结 deterministic semantics。

至少覆盖以下测试。

## 13.1 Raw Factor unit tests

- exact Decimal formula；
- parameter normalization；
- null/warmup behavior；
- wrong input names fail closed；
- wrong input type fail closed；
- output names/type/nullability exact；
- backend resolution exact；
- no hidden Indicator execution。

## 13.2 Graph composition tests

构造：

```text
RollingReturn(short)
RollingReturn(long)
        ↓
Momentum Factor
        ↓
Percentile Scorer
```

验证：

- dependency 显式；
- graph ordering deterministic；
- cycle/missing dependency 继续 fail closed；
- Factor output → Scorer input semantic compatibility 正确；
- alias 不进入 semantic identity（保持现有 contract）；
- graph fingerprint fresh-process stable。

## 13.3 Cross-section deterministic tests

至少包括：

### Input ordering independence

同一语义数据用不同 instrument physical order：

```text
A,B,C,D
D,C,B,A
C,A,D,B
```

结果必须相同。

### Dataset partition independence

不同 Parquet physical partition/order，semantic Dataset 相同：

```text
score result must be identical
```

### Timestamp ordering independence

physical row order 变化但 canonical event-time facts 相同：

```text
result must be identical
```

### Tie behavior

例如：

```text
A = 1
B = 1
C = 2
```

冻结 exact average-rank expected scores。

### Direction

同一 raw values：

```text
HIGHER_IS_BETTER
LOWER_IS_BETTER
```

结果应精确互补（考虑 quantization contract）。

### Missing

覆盖：

```text
one null
multiple null
all null
warmup null
```

验证 null instrument identity 不丢失且不会被填值。

### Single eligible instrument

```text
N = 1 → score = 0.5
```

### Boundary

任何非 null score：

```text
0 <= score <= 1
```

### Duplicate / misaligned input

exact key 冲突、缺失 required input、non-canonical rows 必须 fail closed。

## 13.4 Fresh-process determinism

两个独立进程使用：

```text
same verified Dataset Snapshot
same canonical Calculation Graph
```

必须获得：

```text
same graph fingerprint
same calculation fingerprint
same logical Factor Value
same logical Factor Score
same Result content identity
same Calculation Result fingerprint
```

按当前 Result Store contract 能验证多少就冻结多少，不要伪造 reference。

## 13.5 Existing Indicator regression

P7.5 改 executor 后，必须证明 existing Indicator-only Research Graph：

- output values 不变；
- output partition logical content 不变；
- existing golden references 不变；
- calculation fingerprints 不变；
- Result fingerprints 不变（如果当前 tests/reference 已冻结）。

这是 P7.5 的核心 regression gate。

## 13.6 Result Store integration

Factor/Scorer result：

- commit；
- verified reload；
- content hash；
- semantic hash；
- atomic publish；
- idempotent same result；
- deterministic conflict；
- corrupt target fail closed；
- no repair/overwrite。

## 13.7 Research Job integration

同一 Plan：

```text
run 1 → EXECUTED
run 2 → REUSED
```

验证第二次不会执行 backend。

commit 前中断/重新进入、commit 后 outcome 前重新进入的现有 deterministic recovery semantics 不得回归。

## 13.8 Introspection tests

- type descriptor round-trip/deterministic ordering；
- parameters/input/output semantic 可读取；
- provider/class/path 不污染 semantic identity；
- Registry listing（如新增）稳定排序；
- descriptor 不可变或只读。

## 13.9 Architecture tests

新增 AST/import gates，至少保证：

```text
research factor/scorer implementation
    !→ Trading Runtime
    !→ Cluster
    !→ Strategy
    !→ Broker
    !→ Account
    !→ Order
    !→ Position
    !→ Risk
    !→ Reservation
    !→ Transaction
    !→ mutable Trading Factor lifecycle
```

同时：

```text
calculation core !→ concrete factor plugin
```

# 15. Error model

继续使用 P7.2/P7.4 的 fail-closed、stable code 原则。


优先复用现有 error family/code；只有当前语义无法精确表达时才新增。

# 23. P7.5 Definition of Done

# 26. 最后原则

P7.5 成功的标志不是代码量，也不是 Factor 数量。

真正的成功标准是：

```text
同一个 verified Dataset
+
同一个 canonical Calculation Graph
+
同一个 exact semantic version

无论输入 physical order、process、reuse path 如何变化

都得到同一个 Raw Factor Value
和同一个 Factor Score
并通过同一个 immutable Calculation Result / Research Job authority 收敛。
```

同时，工程必须能够清楚回答：

```text
这个 Factor 用了哪些 Indicator / Feature？
每个输入/输出是什么类型和语义？
Factor 原始值是什么？
Score 是如何得到的？
方向、tie、missing、numeric 规则是什么？
为什么这个结果具有这个 identity？
为什么重新执行不会产生另一个 authority？
```

如果这些问题不能通过 Definition / Graph / Result / Job 直接回答，那么 P7.5 还没有真正完成。
