Do not create a second Product Kernel readiness implementation merely for OpenAPI generation.


If:

```python

```

There must not be:

```text

Test composition            → Kernel readiness
OpenAPI composition         → old Research-only composition
```

The same application factory must have one deterministic composition meaning.

---

## 2.3 Same public API semantics → same canonical OpenAPI

K1 changes product lifecycle composition, not Research HTTP semantics.

Therefore the expected invariant is:

```text

+ same request DTOs
+ same response DTOs
+ same status semantics
+ new internal Kernel readiness composition

→ same canonical OpenAPI
```

Do not regenerate and commit a changed OpenAPI file merely to make the gate pass.

If canonical OpenAPI changes, stop and explain why before accepting the change.

---

## 2.4 Unknown or inconsistent state → fail closed

If the current repository no longer matches the assumed failure path, inspect and determine the real root cause.

Do not:


