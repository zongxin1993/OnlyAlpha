# 2. 第一性原则

整个实现必须服从以下原则。

---

## 2.1 Identity 是函数，不是标签

如果：

```text
identity = X
```

则系统必须满足：

```text
X → exactly one semantic object
```

严禁：

```text
X → Object A
X → Object B
```

即使：

```text
A != B
```

只要它们声明同一个 identity：

```text
candidate_fingerprint
calculation_fingerprint
statistics_fingerprint
```

就必须 fail closed。

---

## 2.2 Canonicalization 必须由 semantic owner 保证

错误：

```text
Producer
先帮 Result Plan 排好序
    ↓
Result Plan 默认 caller 很规矩
```

正确：

```text
Result Plan
自己定义或强制 canonical form
```

因为未来 producer 可能来自：

```text
Definition Resolver
Specification replay
PostgreSQL restore
HTTP
CLI
Agent
Migration
Tests
```

Domain owner 不能依赖 caller 隐式遵守排序规则。

---

## 2.3 Same semantic fact 必须得到 same identity

必须满足：

```text
same semantic composition
→ same canonical representation
→ same Result Plan fingerprint
```

例如：

```text
Candidate Statistics membership = {A, B}
```

不能因为输入顺序：

```text
(A, B)
```

或：

```text
(B, A)
```

得到不同 identity。

---

## 2.4 REUSED 是一个需要证据的结论

`REUSED` 实际意味着：

> 当前提交的 semantic candidate 与已发布 immutable Artifact 是同一个 semantic object。

因此必须先证明：

```text
incoming candidate itself is valid
```

然后才能比较：

```text
incoming semantic identity
vs
existing immutable identity
```

绝不能：

```text
target exists
→ trust incoming claimed fingerprint
→ REUSED
```

---

## 2.5 Invalid candidate 永远不能被 REUSED

必须冻结：

```text
invalid candidate
→ ARTIFACT_INVALID
```

与 target 是否存在无关。

不能出现：

```text
target absent
→ invalid candidate fails

target exists
→ same invalid candidate becomes REUSED
```

这是本任务最重要的 Artifact invariant。

## 9.2 推荐实现


# 39. 推荐 commit 顺序

修改 Scientific Store 后：

```python
def commit(candidate):
    admitted = self._admit(candidate)

    target = self._target(
        admitted.result.manifest.research_result_fingerprint
    )

    if target.exists():
        return self._reuse_existing(admitted, target)

    ...
```

关键不是变量名。

关键是：

```text
_admit
MUST happen before
target.exists()
```

# 40. `_reuse_existing()` 不承担 incoming validation

`_reuse_existing()` 只负责：

```text
1. load_verified existing immutable Artifact
2. compare semantic Artifact identity
3. REUSED or DETERMINISTIC_CONFLICT
```

不要再让它偷偷做完整 candidate admission。

Trust boundary 应明确。

---

# 41. Race Semantics 必须保持

P8.4.2.1 已经正确实现：

```text
rename loser
→ target now exists
→ verify winner
→ REUSED / CONFLICT
```

P8.4.2.2 不得破坏。

新增 `_admit()` 后 race 流程仍然：

```text
candidate admitted once
↓
stage
↓
rename loses
↓
verify winner
↓
reuse/conflict
```

无需再次做 incoming full admission。

---

# 42. Staged Verification 必须继续保留

即使 `_admit()` 已验证 in-memory candidate，

写盘后仍必须：

```text
_read_verified(stage)
```

因为：

```text
Parquet serialization
JSON serialization
filesystem
schema
byte hash
```

是新的 trust boundary。

不能因为有 admission 就删掉 staged verification。
