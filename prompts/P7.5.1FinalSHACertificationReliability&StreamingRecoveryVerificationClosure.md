P7.5.1 解决的问题不是：

> “让一个 timeout test 通过。”

> **证明 Streaming Recovery 的完成语义由状态和 authority 决定，而不是由 wall-clock luck / OS thread scheduling 决定。**

```text

+
```

# 4. 必须保持的核心不变量

## Invariant 1 — Repository Is Source of Truth

每次设计和实现都以当前 HEAD 为准。

禁止为了匹配旧 Prompt 强行修改已经演进的正确实现。

---

## Invariant 2 — Single Semantic Writer

Streaming Runtime 中所有 MarketData semantic mutation 必须继续只有一个正式入口。

包括：

```text
normal realtime update
historical recovery update
buffered realtime catch-up update
```

必须全部经过唯一 canonical processing authority。

禁止出现第二个直接：

```python
MarketDataProcessor.process(...)
```

的旁路。

如果当前已有：

```text
OnlyStreamingProcessingLane
```

或等价 component，则优先继续强化它，而不是创建平行 abstraction。

---

## Invariant 3 — External I/O != Semantic Authority

Historical recovery loading：

```text
load_bars
historical provider call
recovery source read
```

只负责取得 external facts。

它不得：

- 直接修改 MarketData semantic state；
- 直接调用 `MarketDataProcessor.process(...)`；
- 修改 Strategy；
- 修改 Broker；
- 修改 Account / Position / Order；
- 成为 Runtime phase authority。

Recovery Loader produces facts.

它不能 apply facts。

---

## Invariant 4 — Recovery Is Forward Replay

Gap recovery 必须保持：

```text
Confirmed Frontier
→ detect missing closed bars
→ load historical facts
→ validate exact coverage
→ deterministic normalization
→ replay through SAME semantic processing lane
→ reconcile buffered realtime suffix
→ continuity proof
→ LIVE
```

禁止建立：

```text
special recovery mutation path
direct trading state patch
recovery-only manager mutation
```

---

## Invariant 5 — Phase Has One Authority

Streaming phase 必须由一个正式 authority 拥有。

如果当前已有：

```text
OnlyStreamingPhaseController
```

则所有 phase transition 必须继续经过它。

禁止：

```text
Runtime 自己一份 phase
Worker 自己一份 phase
Recovery 再维护一份 phase
Health 再推导一套可变 phase
```

---

## Invariant 6 — STOP Has Precedence

一旦：

```text
STOPPING
```

建立后：

Recovery 不能再次把 phase 改为：

```text
DEGRADED
RECOVERING
CATCH_UP
LIVE
```

只允许：

```text
STOPPING → STOPPED
```

或正式 shutdown failure：

```text
STOPPING → FAILED
```

如果已有 Processing Lane revoke/cutoff contract：

> revoke 返回后，不允许新的 MarketData semantic processing 开始。

这个 contract 必须保持。

---

## Invariant 7 — Timeout Is Watchdog, Not Correctness

禁止把：

```text
recovery 必须在 10 秒内完成
```

作为业务 correctness。

正确模型：

```text
Correctness
=
state transition / continuity proof / explicit event / revision

Timeout
=
deadlock / stuck-operation watchdog
```

禁止只做：

```text
10s → 30s
10s → 60s
```

除非有非常明确、可证明的 watchdog budget authority，并且根因不是 synchronization defect。

即使最终调整 timeout，也必须先证明：

- 为什么旧值不是合法 watchdog；
- 新值的 authority 是什么；
- 为什么它不会继续依赖偶然调度。

---

## Invariant 8 — Failure Must Be Diagnosable

异步 watchdog failure 不能只输出：

```text
assert None is not None
```

必须能够从现有 authority 得到足够诊断信息。

诊断对象只能是：

```text
read-only projection / snapshot
```

不能成为新的 mutable authority。


```text

```

# 8. 推荐增加的只读诊断能力

根据当前实现，设计最小 immutable diagnostics snapshot。

概念上可以包含：

```python
@dataclass(frozen=True)
class OnlyStreamingRecoveryDiagnostics:
    phase: OnlyStreamingPhase
    phase_revision: int
    recovery_generation: int
    recovery_plan_present: bool
    processing_lane_revoked: bool
    worker_alive: bool
    worker_failure: str | None
    source_connected: bool
    subscription_active: bool
    last_closed_bar_end: ...
    expected_recovery_frontier: ...
    buffered_suffix_count: int
```

**这只是概念，不要机械照抄。**

原则：

- 从已有 authority 读取；
- immutable；
- deterministic；
- 不写状态；
- 不维护 parallel lifecycle；
- 不成为第二 Recovery Manager；
- 不含对 identity 有影响的 wall-clock 时间；
- 生产代码中如已有 health/snapshot/read model，优先复用。

如果不需要新增 production public API，也可以只提供 package-private diagnostic snapshot。

# 24. Final-SHA Certification 是最终 authority

本地完成后：

1. 所有修改进入一个 immutable final commit；
2. 获取 exact 40-char SHA；
3. 对这个 SHA 触发正式：
   `Final-SHA Certification`
4. 每一个 mandatory job 必须 success；
5. final verdict 必须：
   `ACCEPTED`

任何：

```text
failure
cancelled
skipped
missing
```

都不能算完成。


```text

```
