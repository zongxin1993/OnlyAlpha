# 1. Task Purpose

P9.K.3 establishes the **single Product HTTP Control Plane**.

K0 answered:

```text
Who owns authority?
```

K1 answered:

```text
When may product mutation occur?
→ OnlyAlphaKernelHost READY
```

K2 answered:

```text
Where does product mutation/read intent enter internally?
→ Product Command / Query Boundary
```

K3 must answer:

> How does an external HTTPS/JSON request map uniquely and deterministically into those Product Commands / Queries without giving FastAPI, routes or DTOs business authority?

Target architecture:

```text
External Actor
    ↓ HTTPS / JSON
OpenAPI Product Contract
    ↓
FastAPI Product Adapter
    ↓
API DTO / explicit mapping
    ↓
Product Command / Query
    ↓
OnlyProductCommandDispatcher / OnlyProductQueryDispatcher
    ↓
Existing Application / Domain Authority
    ↓
Authoritative Fact
```

The task is **not** to create more business services.

The task is to remove HTTP's ability to choose or directly invoke authoritative mutation paths.

# 2. Governing First-Principles Rules

## 2.1 One HTTP semantic operation → one Product intent

For every supported Product HTTP operation:

```text
one HTTP operation
→ one explicit API DTO/path/header mapping
→ one Product Command or Query
→ one Dispatcher
→ one existing authoritative path
```

There must not be two production mutation paths for the same intent.

Forbidden end-state:

```text
HTTP Route A
→ Product Command Dispatcher

HTTP Route B
→ OnlyResearchCommandService directly
```

## 2.2 FastAPI is an adapter, never an authority

FastAPI may own:

```text
HTTP method/path
header parsing
query/path parsing
Pydantic validation
Command/Query construction
HTTP response mapping
HTTP error mapping
OpenAPI projection
```

FastAPI must not own:

```text
Research Run transition
Strategy Freeze
Promotion legality
fingerprint calculation
CAS/retry loops
PostgreSQL writes
business idempotency truth
runtime lifecycle
semantic repair
```

## 2.3 API DTO ≠ Product Command ≠ Domain model ≠ Persistence schema

Maintain separate schema worlds:

```text
API Schema
→ transport compatibility

Product Command / Query / Application Schema
→ product intent semantics

Domain Schema
→ business semantics

Persistence Schema
→ storage implementation
```

Use explicit mappings.

Correct:

```text
HTTP JSON
→ Pydantic DTO
→ Product Command
→ Dispatcher
→ Application Authority
```

Incorrect:

```text
Pydantic DTO
→ Domain persistence directly
```

Do not make Product Commands inherit `BaseModel` merely for transport convenience.

## 2.4 One mutation admission authority

Every Product mutation remains guarded by:

```text
OnlyAlphaKernelHost.assert_mutation_ready()
```

through K2's Product Command Dispatcher.

HTTP readiness checks may project Kernel status, but they are not a second mutation authority.

Do not introduce:

```text
api_ready
route_ready
product_ready flag
research_ready mutation authority
```

## 2.5 Same public HTTP semantics → same OpenAPI

K3 changes the internal authority path, not the public Research v2 contract.

Expected invariant:

```text
same route
+ same method
+ same header semantics
+ same DTOs
+ same response semantics
+ same error semantics
+ new Product Boundary path

→ same canonical OpenAPI
```

Do not regenerate a changed canonical OpenAPI merely to make tests pass.

If canonical OpenAPI bytes/semantics change unexpectedly:

```text
STOP
→ investigate root cause
```

## 2.6 Unknown composition defect fails closed

If a Product Dispatcher cannot resolve a Command/Query that the HTTP composition is supposed to support:

```text
fail closed
```

Do not fallback to the old direct service path.

Forbidden:

```python
try:
    dispatcher.dispatch(command)
except UnsupportedProductCommand:
    research_command_service.submit_research_run(...)
```

Such fallback would reintroduce multiple authoritative product entrances.

## 2.7 Minimum sufficient mechanism

Do not introduce:

```text
generic HTTP command router
reflection-based route generation
generic API Gateway
GraphQL
CQRS framework
service locator
DI framework
message bus
Kafka
NATS
gRPC
event sourcing framework
automatic DTO→Command reflection mapper
```

Hand-written explicit mappings are preferred.

# 5. Frozen K3 Core Invariants

## INV-K3-01 — One Product HTTP Control Plane

There must be one canonical production Product HTTP server/composition root.

Target:

```text
onlyalpha-api
→ one Product HTTP adapter
→ one mutation-capable Kernel Host
→ one Product Command topology
```

Do not create a second mutation-capable Product HTTP server.

## INV-K3-02 — HTTP mutation cannot directly call mutation authority

After K3 closure, canonical Research Run HTTP mutation routes must not directly invoke:

```text
OnlyResearchCommandService
Strategy mutation service
PostgreSQL mutation store
Engine mutation API
Runtime mutation API
```

They must produce Product Commands and dispatch them.

## INV-K3-03 — Research Run HTTP reads use Product Query Boundary

Canonical Research Run GET/List routes must use the Product Query Boundary.

## INV-K3-04 — Product Command/Query remain transport-neutral

`src/onlyalpha` must continue to have zero dependency on:

```text
fastapi
starlette
pydantic transport DTOs
HTTP Request
HTTP Response
onlyalpha_api
```

## INV-K3-05 — Public Research HTTP semantics remain unchanged

Preserve current semantics including:

```text
/api/v2/research/runs
/api/v2/research/runs/{run_id}
/api/v2/research/runs/{run_id}/cancellation

Idempotency-Key semantics
202 Accepted semantics
Location header
existing response DTOs
existing pagination/cursor semantics
existing error/status mappings
```

Do not introduce `/api/v3` or `/product/v1` merely because K3 is a new internal architecture stage.

## INV-K3-06 — No fallback mutation path

If Product composition is wrong:

```text
fail
```

Do not fallback to direct Research service invocation.

## INV-K3-07 — One mutation-capable Kernel Host per Product server

V1 remains a modular monolith.

Do not configure:

```text
uvicorn --workers N
```

where each worker would construct its own mutation-capable Kernel Host.

HA / leader election / epoch / fencing remain later architecture work.

## INV-K3-08 — HTTP idempotency identity remains operational only

Transport values such as:

```text
Idempotency-Key
request ID
actor
JWT
IP
route
API version
headers
```

must never enter:

```text
Dataset fingerprint
Calculation identity
Candidate fingerprint
Strategy fingerprint
```

K3 must preserve existing Research idempotency authority.

```text

```

```text

```

```text
current verified fact

future frozen target
= PostgreSQL 18.x

target declaration
≠ verification
```

K3 is correct when HTTP becomes a replaceable adapter, K2 becomes the unique product semantic entrance beneath it, public behavior remains deterministic, and PostgreSQL 18 is recorded as the future target without falsifying current evidence.
