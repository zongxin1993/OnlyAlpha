# 7. Workstream A — Relative Import Canonicalization

## Problem

The canonical import helper can resolve relative imports only when current module identity is supplied. Guard call sites that use `onlyalpha_imports(source)` without module context can miss:

```python
from ...application import OnlyStrategyPromotionApplicationService
```

## Required Design

Consolidate a path-aware helper, conceptually:

```python
canonical_imports_for_path(path: Path, root: Path)
onlyalpha_imports_for_path(path: Path, root: Path)
```

Pipeline:

```text
Path
→ canonical module identity
→ AST parse
→ ast.Import / ast.ImportFrom
→ resolve relative import
→ canonical authority identity
```

All real-repository scans in K0 guards should use the path-aware form.

## Fail Closed

If a guarded production file contains a relative import and module identity cannot be resolved deterministically:

```text
FAIL
```

Do not return unresolved `...application` and then silently filter it out.

## Required Tests

Cover:

```python
from .application import X
from ..application import X
from ...application import X
```

and:

```python
from ...application import OnlyStrategyPromotionApplicationService as Promotion
```

Also test a nested module such as:

```text
onlyalpha.research.execution.nested.worker
```

Invariant:

```text
same authority
+
absolute import / relative import / alias
→ same canonical identity
```
