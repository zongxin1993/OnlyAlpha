
# 2. Frozen K5 Goal

冻结目标：

```text
Make network retry and Kernel restart normal deterministic scenarios.
```

必须完成：

```text
- generalize P8 idempotency principles for externally retryable Product mutations
- define/reuse durable operation resources where genuinely needed
- prove response-loss retry does not duplicate authoritative work
- recover incomplete command/session state from durable authorities
- reconcile projections after crash
- fail closed on command-id reuse with changed canonical intent
- use deterministic crash barriers, never timing guesses
```

Exit Criterion：

```text
Restart/retry converges to one outcome
and does not produce duplicate semantic/business authority.
```

# 3. First-Principles Invariants

在写代码前，把这些视为不可破坏的 Task Contract。

## INV-K5-001 — One External Command Identity Authority

一个 External Command ID / Idempotency-Key 只能绑定一个 canonical command intent。

```text
same command id + same command
→ replay / converge to same authoritative outcome

same command id + different command
→ fail closed before any new business mutation
```

---

## INV-K5-002 — Transport Identity Is Not Semantic Identity

以下内容绝对不得进入：

```text
Dataset fingerprint
Calculation fingerprint
Research Candidate fingerprint
Strategy fingerprint
Strategy Freeze semantic relation
Equivalence semantic identity
```

禁止进入 semantic fingerprint 的典型字段：

```text
request_id
idempotency_key
external_command_id
actor
JWT
IP
User-Agent
HTTP route
API version
HTTP headers
server hostname
PID
wall-clock retry metadata
```

Operational/audit identity 与 semantic/business identity 必须严格分离。

---

## INV-K5-003 — Command Receipt Is Not Business Truth

Command receipt 只能表达：

```text
external command identity
→ authoritative resource reference
```

不能复制：

```text
ResearchRun state
Strategy state
Runtime state
business result DTO
semantic payload
```

Replay 时必须重新通过 authoritative Store / Query 读取当前权威事实。

---

## INV-K5-004 — HTTP Lifetime Does Not Own Long-running Work

模式必须保持：

```text
POST Command
↓
durable admission / authoritative resource
↓
202 / authoritative resource identity
↓
HTTP request ends

Worker / Kernel / Runtime continues independently
```

当前 `ResearchRun` 已经是正确的 durable long-running resource。

不得新增一个通用：

```text
ProductOperation(PENDING/RUNNING/SUCCEEDED/FAILED)
```

去镜像 `ResearchRun.state`。

---

## INV-K5-005 — Recovery Is Authority-driven

恢复必须依据：

```text
immutable semantic authority
operational PostgreSQL authority
runtime durable facts
external venue/broker authority where applicable
```

禁止：

```text
pickle whole Kernel
restore process memory snapshot as truth
guess last execution line
replay every historical command blindly
```

---

## INV-K5-006 — Semantic Truth Wins Over Projection

合法方向：

```text
verified immutable semantic truth
→ rebuild missing projection
```

非法方向：

```text
projection
→ rewrite semantic truth
```

如果：

```text
semantic truth != existing projection
```

必须：

```text
fail closed
```

---

## INV-K5-007 — RECOVERING Is Mutation-closed

Kernel 只有：

```text
READY
```

才允许 Product mutation。

在：

```text
CREATED
BOOTING
VERIFYING
RECOVERING
DRAINING
FAILED
STOPPED
```

收到 mutation 必须被拒绝，并且：

```text
no command receipt
no business mutation
```

---

## INV-K5-008 — No Generic Workflow Engine

本任务禁止引入：

```text
Temporal
Celery
Redis durable queue
Kafka
NATS
generic workflow DSL
generic event-sourcing framework
multi-master Kernel
leader election
```

P9.K.5 不是为了“架构漂亮”，而是为了最小充分地封闭真实 crash/retry 问题。

# 6. K5.1 — Product Command Identity Contract

## Goal

冻结统一 operational retry vocabulary，但不改变业务语义。

建议在 Application 层增加最小模型，例如：

```text
src/onlyalpha/application/product_command_identity.py
```

可考虑定义：

```text
OnlyProductCommandId
OnlyProductCommandKind
OnlyProductCommandFingerprint
OnlyProductCommandOutcomeRef
OnlyProductCommandReceipt
```

命名可根据现有工程风格微调，但职责不可漂移。

---

## 6.1 Product Command ID

建议：

```text
canonical UUID4
```

必须跨：

```text
HTTP retry
API process restart
machine restart
```

稳定。

禁止：

```text
database auto increment
PID
hostname
random process-local token
HTTP request id substitution
```

---

## 6.2 Command Kind

Command identity 不得只依赖 fingerprint。

必须至少形成：

```text
external_command_id
+
command_kind
+
canonical_command_fingerprint
```

例如：

```text
CREATE_RESEARCH_RUN
CANCEL_RESEARCH_RUN
```

未来 Strategy/Runtime mutation 可复用同一协议。

---

## 6.3 Command Fingerprint

优先复用已有 command-specific canonical fingerprint。

例如 CreateResearchRun 当前已有：

```text
SHA256(canonical({"specification": ...}))
```

不要为了“统一”改变现有 Research fingerprint 行为。

Product-level binding 可以是：

```text
command_kind
+
existing command_fingerprint
```

而不是重新发明业务 payload。

---

## 6.4 Outcome Ref

只允许引用权威资源：

```text
RESEARCH_RUN → run_id
future STRATEGY → strategy_fingerprint
future BACKTEST → durable backtest id
future SIM → durable simulation id
```

Outcome ref 不是完整结果副本。

## Goal

建议新增 PostgreSQL migration：

---

## 7.1 Minimum Schema

概念结构：

```sql
product_command_receipt
-----------------------

command_kind            TEXT NOT NULL

outcome_kind            TEXT NOT NULL
outcome_id              TEXT NOT NULL
accepted_at             TIMESTAMPTZ NOT NULL

```

具体 SQL 约束请按当前 PostgreSQL migration style 实现。

至少：

```text

fingerprint strict lower-case SHA256
known schema version
non-empty command_kind/outcome_kind/outcome_id
```

---

## 7.2 Receipt Store

建议增加窄 persistence port + PostgreSQL adapter。

例如：

```text
OnlyProductCommandReceiptStore
OnlyPostgresProductCommandReceiptStore
```

但不要因为“分层漂亮”而复制 ResearchRun SQL。

**Transaction correctness > physical file purity.**

如果 `ResearchRun + Receipt` 必须一个 transaction，则将 transaction ownership 放在一个明确的 persistence business boundary 中。

不要做：

```text
commit ResearchRun
then
commit Receipt
```

然后依赖 recovery 猜测。

## 7.3 Existing `research_run_submission`

当前 active schema：

```text
research_run_submission(
    submission_key,
    command_fingerprint,
    run_id

```

```text
research_run_submission = External Command authority
```

否则违反唯一性。

建议：

1. migration 0012 从现有 `research_run_submission + research_run` backfill Product Receipt；
2. 历史表物理保留；
3. production code K5 后不再把 `research_run_submission` 作为 active authority；
4. 不再新增写入；
5. architecture test 冻结这一点。

Backfill 例：


# 8. K5.3 — Research Create Idempotency Closure

这是第一条正式 vertical slice。

## 8.1 Public HTTP Contract

保持：

```http
POST /api/v2/research/runs
Idempotency-Key: required canonical UUID4
```

不要改变 request/response DTO。

---

## 8.2 First Request

目标 transaction：

```text
BEGIN

load ProductCommandReceipt(K1)

if absent:
    deterministically prepare ResearchRun R1
    create ResearchRun R1
    create ProductCommandReceipt:
        command_id = K1
        kind = CREATE_RESEARCH_RUN
        fingerprint = F1
        outcome = RESEARCH_RUN:R1

COMMIT
```

只有 commit 成功后才允许返回：

```text
202 Accepted
Location: /api/v2/research/runs/R1
```

---

## 8.3 Retry After Response Loss

客户端再次发送：

```text
K1 + same specification
```

必须：

```text
load receipt K1
kind same
fingerprint same
↓
load authoritative ResearchRun R1
↓
return same R1
```

不能再次：

```text
admission.prepare()
create new Run
```

---

## 8.4 Same Key + Different Spec

必须：

```text
409 conflict
```

并证明：

```text
no new Run
no new Receipt
existing Run unchanged
existing Receipt unchanged
```

---

## 8.5 Concurrency

必须覆盖：

```text
two processes / two DB connections
same key + same command
```

只有一个 durable authoritative outcome。

另一个调用：

```text
replays same outcome
```

而不是：

```text
duplicate Run
```

还必须覆盖：

```text
same key + different command concurrently
```

只有一个 intent 可以成为 authority；另一个 deterministic conflict。

# 9. K5.3 — Research Cancel Idempotency Closure


## 9.1 Backward Compatibility

当前 v2 Cancel 原本不要求 Idempotency-Key。

否则违反 K4：

```text

```

正确方案：

```text

```

行为：

```text

→ retain current natural cancellation behavior

key present
→ K5 strong external-command idempotency
```

---

## 9.2 Cancel Fingerprint

Canonical intent 最小可由：

```json
{
  "run_id": "<canonical run id>"
}
```

派生。

不要把：

```text
actor
request time
HTTP route
```

纳入 fingerprint。

---

## 9.3 With Key

目标行为：

```text
K2 + CANCEL_RESEARCH_RUN + R1
```

第一次：

```text
atomic authoritative cancellation transition
+
receipt K2 → RESEARCH_RUN:R1
```

再次 same key + same R1：

```text

```

same key + R2：

```text
conflict before R2 mutation
```

## Goal

第一次真正使用 K1 已存在但当前 production 为空的：

```text
RECOVERING
```

但 Kernel Host 仍然只做 lifecycle composition。

---

## 11.1 Host Must Stay Thin

禁止：

```python

kernel.recover_strategy()
kernel.repair_database()
```

正确方式：

```text
Application-specific recovery/reconciler
↓
wrapped as OnlyKernelLifecycleStep
↓

```

`OnlyAlphaKernelHost` 不应获得 domain Store writer/service locator。

---

## 11.2 Recovery Scope

建议 K5 当前 production recovery 仅包含真正需要 Kernel startup 完成的项，例如：

```text

2. Strategy Freeze semantic → PostgreSQL projection reconciliation
```

不要把 Research Attempt/lease recovery 拉入 Kernel Host。

Research Worker 的 recovery authority 已经成熟且独立。

```text

invalid SHA256
malformed outcome ref
unknown schema version
impossible mapping
dangling authoritative resource reference where contract requires existence
```

必须：

```text
FAILED
```

不能：

```text
log warning and READY
```

但不要：

```text
re-execute all historical commands
```

Receipt recovery 是：

```text
verify / reconcile
```

不是：

```text
blind replay command log
```

# 15. K5.5 — Deterministic Crash & Response-loss Proof

K5 的 correctness 主要由 failure injection 证明。

禁止：

```python
sleep(1)
kill()
```

必须使用 deterministic barrier。

复用 P8.6 crash test 模式：

```text
child process / ASGI request
↓
reaches named boundary Cn
↓
signals deterministic barrier
↓
test confirms barrier
↓
SIGKILL / response drop
↓
restart / retry
↓
assert convergence
```

Production code 不得加入通用 test-only crash environment switch。

优先把 fault/barrier 放在 test harness / test adapter。
