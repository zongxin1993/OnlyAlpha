# 0. 任务的一句话目标

P8.4.1 的目标是：

> **把 OnlyAlpha 已经存在的 Universe、Calculation、Dataset、Statistics 和 Research Definition Resolver 权威能力，通过严格、确定性、只读的 Discovery Projection 与 Definition Resolution HTTP Contract 对外暴露，使 Web、Python Client 和未来 Agent 能够通过同一个公共协议发现“可以研究什么”，并将 Research Definition 权威解析成 Exact Dataset、Global Candidate Space 和 Exact Research Specification；HTTP 层只负责 transport、projection 与 error ownership，不复制 Research semantics，不创建 Run，不增加新的持久化 authority。**

# 1. 第一性原理

开始设计任何类、DTO 或 endpoint 之前，先明确本任务真正解决的问题。

P8.4.0.x 已经解决：

```text
用户研究意图
        ↓
OnlyResearchDefinition
        ↓
OnlyResearchDefinitionResolver
        ↓
Exact Dataset Snapshot
+
Global Candidate Space
+
Exact Decision Graph
+
Exact Research Specification
+
OnlyResearchWorkloadPlan
```

P8.4.1 **不再解决 Research semantics**。

P8.4.1 解决的是：

```text
外部客户端如何知道：
OnlyAlpha 支持什么？

以及：

外部客户端如何请求：
OnlyAlpha 权威解释这个 Research Definition？
```

因此正确架构是：

```text
Existing Semantic Authorities
        ↓
Read-only Projection
        ↓
HTTP Transport
        ↓
Web / Python / Future Agent
```

绝对不是：

```text
HTTP
↓
重新实现一套 Research semantics
```



# 49. P8.4.1-F — HTTP Error Ownership Closure

这是本阶段必须解决的另一个核心问题。

```text

Artifact
```


不要写：

```python

...
elif "/definitions" in path:
...
elif "/catalog" in path:
...
else:
...
```

一路扩张。

这种设计随着 endpoint 增长会持续恶化。

---

# 51. 正确方向

审计当前 FastAPI app 结构，采用**最小、显式、可审计**的 endpoint-family ownership 方法。

例如可以是：

```text
explicit route names → error family
```

或者当前框架已有更合适的 router metadata。

关键要求：

```text
Command routes
→ Command error contract

Artifact routes
→ Artifact error contract

Definition routes
→ Definition error contract

Discovery routes
→ Discovery/read contract
```

。

不要建立大型：

```text
ErrorRouter Framework
ErrorMiddleware Framework V2
```

。

---

```text

code
path
detail
```

不要丢失 P8.4.0.1 已经修好的：

```text

```

。
