5. P7.12 最重要的 Correctness Closure：
   Web-safe Nanosecond Transport
================================================================

当前 HTTP transport 中：

    ts_event_ns: JSON integer
    next_after_ts_event_ns: JSON integer

对 Python 没问题，

但 Unix nanosecond timestamp 通常远大于 JavaScript safe integer range。

因此：

    P7.12 不允许 Web 通过 Number 接收 exact nanosecond authority。

必须正式修复 HTTP transport。

------------------------------------------------------------
5.1 Query Core 不改
------------------------------------------------------------

保持：

    OnlyResearchStatisticPoint.ts_event_ns: int

以及：

    OnlyResearchStatisticSeriesQuery
    from_ts_event_ns
    to_ts_event_ns
    after_ts_event_ns

Core 继续使用 Python int。

不要因为浏览器限制修改：

- Artifact semantic model；
- Statistics identity；
- Query semantic；
- pagination semantic；
- Research identity。


------------------------------------------------------------
5.2 HTTP Transport 改成 decimal string
------------------------------------------------------------

HTTP：

    ts_event_ns
    next_after_ts_event_ns

必须变为：

    canonical decimal string

示例：

{
    "ts_event_ns": "1780000000000000123"
}

而不是：

{
    "ts_event_ns": 1780000000000000123
}

Cursor 同理。


------------------------------------------------------------
5.3 Request-side 时间参数也必须是 string contract
------------------------------------------------------------

HTTP query params：

    from_ts_event_ns
    to_ts_event_ns
    after_ts_event_ns

OpenAPI contract 必须表达为：

    string

而不是：

    integer

Router/API Adapter：

canonical decimal string
        ↓
validated
        ↓
Python int
        ↓
OnlyResearchStatisticSeriesQuery

Web：

exact decimal string / bigint
        ↓
URL query parameter string

全过程不能经过 JavaScript Number。
