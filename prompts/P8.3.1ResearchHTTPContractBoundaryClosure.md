# 1. 任务目标

完成：

```text
P8.3.1 — Research HTTP Contract Boundary Closure
```

本任务只解决 P8.3 当前存在的一个明确 HTTP transport contract 边界问题：

```text
Full Research API
=
Artifact Query API
+
Research Run Command API
```

当前：

```python
create_artifact_query_app(...)
```

已经为 Artifact Query API 注册：

```python
RequestValidationError
→ Artifact Query error contract
```

例如非法 Artifact Query 参数：

```text
GET /api/v2/research/artifacts/.../series?limit=bad
```

应稳定返回 Artifact Query plane 的错误协议：

```json
{
  "schema_version": 2,
  "code": "INVALID_QUERY",
  "detail": "..."
}
```

但是：

```python
create_research_app(...)
```

基于：

```python
app = create_artifact_query_app(reader)
```

创建 Full Research API 后，又注册了新的：

```python
RequestValidationError
→ Research Run command error envelope
```

因此全局 FastAPI exception handler 可能覆盖 Artifact Query 原有 validation contract。

这会导致：

```text
onlyalpha-artifact-api
```

和：

```text
onlyalpha-api
```

访问完全相同 Artifact endpoint 时，对同一种非法请求返回不同 transport error contract。

这违反当前已经冻结的架构原则：

```text
Artifact Query Plane
≠
Research Command / Operational Plane
```

P8.3.1 的目标就是彻底关闭这个 contract leakage。

---

# 2. 第一性原理

不要把这个任务理解为：

> 修改一个 FastAPI exception handler。

真正的问题是：

```text
一个 HTTP server 中存在两个不同语义边界，
它们不能因为共享 FastAPI App 而失去各自的 transport contract。
```

OnlyAlpha 当前存在两个不同 HTTP boundary。

## Artifact Query Plane

职责：

```text
immutable Artifact
→ read-only query
→ portable consumption
```

它拥有自己的：

```text
query validation
query error taxonomy
response schema
portable API contract
```

它不依赖 PostgreSQL。

---

## Research Run Command Plane

职责：

```text
Research Specification
→ durable Run submission
→ operational Run read
→ cancellation request
```

它拥有自己的：

```text
command validation
operational error taxonomy
Run DTO
Idempotency semantics
```

它依赖 PostgreSQL operational authority。

---

因此：

```text
共享 HTTP process
```

绝不能等价于：

```text
共享 transport semantics
```

必须保证：

```text
Artifact endpoint failure
→ Artifact Query error contract

Run endpoint failure
→ Research Run error contract
```

无论它们运行在：

```text
onlyalpha-artifact-api
```

还是：

```text
onlyalpha-api
```

都必须保持这一原则。

# 3. 本任务核心不变量

修改后必须满足：

```text
same Artifact request
+
same Artifact failure
=
same Artifact response contract
```

无论请求通过：

```text
portable Artifact app
```

还是：

```text
full Research app
```

结果必须一致。

即：

```text
create_artifact_query_app
```

与：

```text
create_research_app
```

对于 Artifact routes 的 HTTP contract 必须 observationally equivalent。

同时：

```text

```

仍必须继续返回：

```json
{
  "error": {
    "phase": "...",
    "code": "...",
    "detail": "..."
  }
}
```

不得为了修 Artifact contract 而破坏 Run API。

# 8. 推荐设计方向

可以评估以下实现方向，但必须根据当前代码选择最简单且边界最清晰的方案。

---

## 方案 A：按 request path 对 RequestValidationError 做显式分发

例如 Full App 中只保留一个：

```python
RequestValidationError
```

handler，然后：

```text
/api/v2/research/runs...
→ Run validation response

/api/v2/research/artifacts...
→ Artifact validation response
```

优点：

```text
简单
显式
改动小
容易测试
```

需要注意：

不能把 path dispatch 写成散落的字符串 hack。

可以建立非常有限的 private helper，例如：

```python
_is_research_run_request(request)
```

但不要建立通用 routing framework。

---

## 方案 B：让 validation 尽量成为 router/local dependency responsibility

如果当前 FastAPI 结构允许在 router/dependency admission 阶段清楚地区分两种错误，可以考虑让错误直接进入：

```text
OnlyResearchQueryError
```

或：

```text
OnlyResearchCommandError
```

再由各自 handler 处理。

如果这个方案需要明显更多 plumbing，则不要为了理论纯洁而增加复杂度。

---

# 29. 最终原则

本任务不是：

> 把所有 HTTP errors 统一。

而是：

> **保证不同 semantic boundary 即使运行在同一个 HTTP application 中，也继续拥有自己的稳定 transport contract。**

最终必须继续成立：

```text
Artifact Query
→ immutable read boundary
→ Artifact error semantics

Research Command
→ operational control boundary
→ Run command error semantics
```

共享：

```text
FastAPI process
```

不能让它们变成：

```text
shared semantic authority
```

先审计当前 HEAD，记录 `TASK_BASE_SHA`，建立能够暴露 Full Research App Artifact validation contract leakage 的 regression test，然后以最小代码修改完成 closure，并执行完整 affected verification。
