# 1. P8.5 的本质

P8.5 不再增加 Research 语义功能。

它真正解决：

```text
系统现在是不是健康？
为什么 Run 不动？
Worker 挂了以后会发生什么？
API/Worker 重启后会发生什么？
PostgreSQL 暂时不可用会发生什么？
schema 如何安全升级？
备份是否真的能恢复？
恢复后是否仍保持唯一事实和确定行为？
```

目标：

> **把当前 Web-native Research 服务从“开发环境可以运行”收敛为“可以长期运行、诊断、重启、升级、备份和恢复”的单机/小团队系统。**

# 2. 第一性原理

OnlyAlpha 当前已有两类事实。

## Operational Truth

PostgreSQL 已拥有：

```text
Research Run
Run revision/state/timestamps/failure
Result/Artifact references
Execution Attempt
Attempt number/state
Worker instance ID
Claim
Lease
Heartbeat
Retry history
Cancellation intent
```

它回答：

```text

```

## Semantic Truth

已有 immutable authorities 拥有：

```text
Dataset Snapshot
Calculation Result
Statistics Result
Research Result
Scientific Artifact
Calculation Graph
Signal Evidence
```

它回答：

```text
研究究竟计算出了什么？
```

因此必须保持：

```text
PostgreSQL → Operational Truth
Immutable Stores → Semantic Truth
```

禁止把 semantic content 复制到 PostgreSQL。

# 4. 确定性原则

```text

same Attempt history
```

```text

线程调度顺序

unordered SQL result
dict/set iteration order
```

# 12. Graceful Stop

把现有：

```text
stop new claims
→ active claim drains
```

升级为正式进程生命周期：

```text
SIGINT / SIGTERM
        ↓
DRAINING
        ↓
stop claiming
        ↓
ACTIVE Attempt keeps heartbeat
        ↓
safe completion
        ↓
exit
```

禁止：

```text
SIGTERM → Run FAILED
```

因为：

```text
process stop != semantic failure
```

如果最终被强杀：

```text
heartbeat stops
→ lease expires
→ Attempt EXPIRED
→ fresh Worker forward recovery
```

不增加 shutdown repair/reset。

# 21. Diagnosis 机械推导

例：

```text
QUEUED + no fresh Worker presence
→ NO_READY_WORKER

QUEUED + age > threshold + Worker present
→ QUEUE_AGED

RUNNING + no ACTIVE Attempt
→ RUNNING_WITHOUT_ACTIVE_ATTEMPT

ACTIVE Attempt + lease_expires_at <= PostgreSQL clock
→ ACTIVE_LEASE_OVERDUE

CANCEL_REQUESTED + no ACTIVE Attempt
→ CANCELLATION_RECOVERY_PENDING
```

时间阈值必须：

```text
explicit
configuration-owned
documented
```

但 threshold 只能用于 diagnosis，不能直接决定 FAILED/EXPIRED。
