# 1. 先理解问题，不要先写代码

P8.4.4 不是“给 Research 页面加几个图表”。

从第一性原理看，OnlyAlpha 当前已经解决了：

```text
Research Definition
→ deterministic Resolution
→ exact Specification
→ durable Run
→ Scheduler / Worker
→ OnlyResearchRuntime
→ immutable Result
→ Scientific Artifact V2
→ Query API
```

P8.4.4 要解决的问题是：

```text
immutable scientific evidence
        ↓
strict read contract
        ↓
deterministic presentation projection
        ↓
human-understandable scientific workstation
```

研究人员需要回答：

```text
我正在看哪一个 exact Result / Artifact？

这个 Candidate 对应什么 exact parameter assignment？

这个 Candidate 的时间序列是什么？

哪些 Entry / Exit Signal 是 Runtime 真正产生的？

IC / RankIC evidence 是什么？

不同 Candidate 的参数与 Statistics evidence 如何比较？

这个 Candidate 最终解析成了哪一张 exact Calculation / Decision Graph？

Builder 中的研究意图最终对应了什么 execution topology？

当图表可疑时，我能否查看背后的 exact evidence？
```

P8.4.4 的核心目标不是“创造更多数据”，而是：

> **让已有 immutable scientific evidence 可见、可理解、可比较、可追溯、可审计。**

# 2. 第一性原则

实现过程中始终使用以下原则判断设计是否正确。

## 2.1 Truth 必须先存在，Viewer 才能展示

```text
Viewer presents truth.
Viewer never creates truth.
```

正确的数据方向：

```text
Existing Immutable Authority
        ↓
Scientific Artifact
        ↓
Query Service
        ↓
HTTP Read DTO
        ↓
Strict Web Admission
        ↓
OnlyAlpha Presentation Projection
        ↓
Renderer Adapter
        ↓
Chart / Graph
```

禁止：

```text
Browser
→ 重新计算 Factor
→ 重新计算 Signal
→ 重新计算 IC / RankIC
→ 重新构造 Candidate
→ 重新解析 Graph
→ 产生“新的 Research truth”
```

如果 Viewer 想显示的事实当前 Artifact / Query evidence 不支持：

```text
DO NOT guess
DO NOT infer a semantic fact
DO NOT calculate an authoritative substitute in React/ECharts
DO NOT read internal Parquet directly

→ fail closed
→ expose unavailable / unsupported honestly
→ or minimally extend the immutable read projection if and only if the required fact already exists in an existing authority
```

---

## 2.2 唯一性原则：One Domain → One Write Authority

P8.4.4 不得创建以下任何第二 authority：

```text
CandidateStore
GraphStore
SignalStore
EvidenceStore
StatisticsStore
ResultStore
ArtifactStore
PredicateStore
ViewerStateStore that pretends to be semantic persistence
```

现有 authority 继续唯一：

```text
Dataset truth
→ existing Dataset authority

Calculation truth
→ existing Calculation Registry / Result authority

Statistics truth
→ existing Statistics Result authority

Research Result truth
→ existing Research Result authority

Artifact truth
→ existing immutable Artifact authority

Candidate identity
→ existing resolved Specification / Result lineage

Graph identity
→ existing exact Calculation Graph authority

Run operational truth
→ existing PostgreSQL Research Run authority
```

Web 只能拥有：

```text
selected tab
selected candidate
selected instrument
selected published series
selected statistics series
selected exact timestamp / viewport
chart zoom / layout
graph expansion / inspector selection
loading / error state
```

这些是 presentation state，不得参与 Research semantic identity。

---

## 2.3 确定性原则

对于同一个：

```text
Artifact
+
exact query selector
+
same admitted read payload
```

Viewer 的 admitted model 和 presentation projection 必须确定。

不得依赖：

```text
object insertion order
random ID
current wall-clock time
locale-dependent parsing
implicit floating coercion
unstable Array iteration from unordered input
renderer-generated identities
DOT layout as semantic identity
```

Renderer layout 可以非语义地变化，但：

```text
semantic node identity
candidate identity
series selector
statistics identity
exact values
```

不能变化。

---

## 2.4 Fail Closed

遇到以下情况必须显式失败：

```text
unknown schema
unknown graph shape
invalid SHA / fingerprint
invalid decimal string
invalid nanosecond timestamp
unknown value_kind
candidate not in artifact membership
series not in artifact membership
graph candidate mismatch
unsupported Statistics evidence
malformed API payload
ambiguous presentation selector
```

不要 silently ignore、fallback、猜测或自动修复 semantic data。

---

## 2.5 最小充分设计

不要因为要做 Viewer 就引入新的平台。

禁止无依据增加：

```text
new backend service
new database table
new PostgreSQL schema
new message queue
new cache authority
new graph engine
new chart framework
new state-management framework
new domain identity framework
new optimization framework
new data warehouse
ClickHouse
SSE/WebSocket
```

如果现有 React Query + API + immutable Artifact 能解决问题，就使用现有能力。

只增加 P8.4.4 真正需要的代码。

## Stage 0 — Scientific Read Contract Closure

### 目标

在 Viewer 大规模开发前，将所有 P8.4.4 必需的 read evidence contract 变成：

```text
strict
versioned
fail-closed
generated
test-covered
```

优先关闭 Graph DTO。

### 7.0.1 Graph Projection DTO

先读取：

```text
OnlyCalculationGraphDefinition
its exact to_dict()/from_dict() contract
graph fingerprint construction
node / edge / port / parameter representation
role-bearing terminals
```

然后基于 **现有 Graph truth** 设计 read-only transport。

要求：

1. 不再使用：

```python
graph: dict[str, object]
```

2. 不再使用：

```ts
z.record(z.string(), z.unknown())
```

3. API DTO 必须：

```text
strict
extra=forbid
versioned where required
typed nested structures
stable field meaning
```

4. OpenAPI 必须准确生成该结构。

5. `generated.ts` 必须由现有生成命令更新，不得手写生成文件。

6. Zod 必须是 strict admission。

7. malformed Graph payload 必须 fail closed。

8. Graph DTO 是：

```text
read projection
```

而不是：

```text
new graph definition
new graph semantic model
new graph identity authority
```

### 7.0.2 不要过度设计 Graph DTO

如果现有 `OnlyCalculationGraphDefinition` 已有稳定 canonical serialized shape：

优先机械映射。

不要额外发明：

```text
GraphV3
UI Graph Schema
SemanticGraphStore
GraphNodeRegistry
DOT persistence
Graph ORM
```

只加入 Viewer 真正需要且现有 Graph truth 已经证明的字段。

### 7.0.3 API contract tests

至少证明：

```text
Domain Graph
→ DTO
→ JSON
→ OpenAPI generated type
→ Zod admission
```

保持一致。

错误字段：

```text
missing required field
unknown field
wrong fingerprint format
wrong scalar type
malformed node/edge/port
unsupported schema version
```

必须被拒绝。

### Exit Gate

Stage 0 完成条件：

```text
Web Graph Inspector 不再依赖 unknown graph shape。
```

## Stage 5 — Candidate Analysis

### 目标

让 Research Sweep 从 fingerprint 列表变成可理解的参数空间，同时保持 Candidate identity 唯一且由现有 authority 提供。

### Candidate Table

必须能够展示：

```text
candidate_fingerprint
canonical assignment
calculation_fingerprint
graph_fingerprint
statistics_fingerprints
```

普通展示优先 parameter assignment，exact fingerprint 放 Inspector。

### 选中 Candidate

全工作台使用同一个：

```text
selectedCandidateFingerprint
```

驱动：

```text
published variables
signals
statistics
exact graph
```

不能每个 panel 自己“按参数猜 Candidate”。

### Visualization policy

遵循：

```text
1 sweep dimension
→ scatter / line-style metric view

2 sweep dimensions
→ heatmap

3+ dimensions
→ parallel coordinates + table
```

### 关键约束：不要在 Browser 发明 Candidate score

一个常见错误是：

```text
load IC series
→ Browser mean(IC)
→ 把 mean(IC) 当 Candidate authority metric
→ heatmap
```

这是禁止的。

如果当前 artifact/query 只提供 time-indexed authoritative IC/RankIC rows，而没有 authoritative candidate-level aggregate：

优先使用：

```text
explicit selected Statistics
+
explicit exact ts_event_ns
+
authoritative statistic_value at that timestamp
```

作为 Candidate surface 的显示切片。

也就是说：

```text
Candidate Surface
= exact Statistic evidence at one explicitly identified time slice
```

而不是：

```text
Browser-invented aggregate score
```

可提供：

```text
Statistics selector
timestamp selector
```

默认 timestamp 如需自动选择，应是一个明确、确定、可解释的 presentation rule，例如：

```text
latest admitted/common exact timestamp
```

并在 UI 中显示当前选中的 exact time。

不要偷偷用：

```text
mean
median
last valid without showing it
rolling aggregation
Sharpe-like ratio
```

如果仓库当前已经存在 authoritative candidate summary，则使用现有 authority，不要再算一次。

### Assignment typing

不要把 arbitrary `unknown` 强行转换成 number。

只能对当前 exact canonical assignment 中被证明是 numeric 的维度建立数轴/heatmap。

非 numeric sweep：

```text
STRING
BOOLEAN
```

应使用 categorical presentation 或 table，而不是伪造连续数轴。

### 6.1 Exact Graph

数据来源：

```text
selected candidate
→ Query API
→ exact graph read DTO
→ strict Zod
→ OnlyAlpha graph presentation model
→ DOT
→ @viz-js/viz
→ SVG
```

Exact Graph 应尽量保留已有 evidence：

```text

exact calculation type
semantic version
resolved parameters
ports
edges
published outputs
role-bearing terminals
calculation_fingerprint
graph_fingerprint
candidate_fingerprint
```

具体能显示什么以当前 exact Graph truth 为准。

不要猜不存在的字段。

### Node Inspector

支持点击稳定 projection node ID，展示：

```text
semantic label
exact type/version
parameters
inputs / outputs
roles
fingerprints where relevant
```

Projection node ID 应由已有 exact node identity 确定性生成或直接使用现有稳定 identity。

不得使用：

```text
Math.random()
Date.now()
Graphviz generated DOM ID
array index as semantic identity
```

### 6.2 Semantic Graph

Semantic Graph 是 **presentation projection**，不是第二 Graph truth。

它可以：

```text
hide low-level internal predicate plumbing
group related exact nodes
show Calculation / Eligibility / Entry / Exit / Target / Statistics relationships
use human-readable labels
```

但只能基于 exact Graph / Artifact 已证明的信息。

如果 exact evidence 不足以证明某个关系：

```text
do not invent it
```

不要重新调用 Definition Resolver 去“重建”一套当前 Artifact 的 semantic graph。

不要从 Builder draft 读取历史意图作为 Result truth。

Result Inspector 应以 Result/Artifact evidence 为依据。

### 6.3 DOT

DOT 只在 adapter 内部生成。

禁止：

```text
persist DOT as Graph authority
send DOT back to backend as execution input
parse edited DOT
node editor
drag-to-change semantics
```

可以允许：


## Stage 8 — Loading / Pagination / Failure / Scale Boundary

### 目标

保证 Viewer 在真实 Scientific Artifact 上可用，而不是只在小 fixture 上工作。

### 要求

- 使用现有 React Query / API client；
- query key 必须包含 exact identity selectors；
- candidate 变化必须正确失效/切换数据；
- instrument 变化必须正确隔离缓存；

- 不要用 fake percentage progress；

2. 做最小读取优化；
3. 将真正的数据平台/hardening 问题留给 P8.5；
4. 不破坏当前 authority。
