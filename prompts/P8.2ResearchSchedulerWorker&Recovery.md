0. 任务定位
============================================================

P8.2 不是“写一个后台 while loop”。

P8.2 要解决的根本问题是：

已经被 PostgreSQL durable 接受的 ResearchRun，

如何在：

- 多 Worker 并发竞争
- Worker crash
- Server/process restart
- lease timeout
- stale worker 恢复
- 部分 immutable semantic facts 已经提交
- cancellation
- retry

这些情况下，

仍然能够：

1. 保持唯一 authoritative execution ownership；
2. 不产生第二套 Research semantic truth；
3. 不允许 stale Worker 提交 operational outcome；
4. 不需要 mutable Research checkpoint；
5. 最终收敛到真实 terminal outcome：

COMPLETED
FAILED
CANCELLED

============================================================
24. Lease 的第一性定义
============================================================

Claim 不能意味着：

Worker 永久拥有 Run。

Attempt 必须拥有：

Lease 表达：

“在这个时间以前，
当前 Worker 被允许代表这个 Attempt执行和提交 operational result。”

Lease expired：

不证明 process 物理死亡。

只证明：

Worker 已失去 authoritative execution ownership。

============================================================
25. Lease 时间 Authority
============================================================

P8.2 默认设计决策：

Lease 使用 PostgreSQL server clock
作为唯一 lease-time authority。

原因：

Lease 是跨 process / potential cross-host coordination fact。

不能依赖不同 Worker 的 local wall clock。

推荐：

PostgreSQL clock
→ claimed_at
→ heartbeat time
→ lease_expires_at

使用适合 lease correctness 的 PostgreSQL time function，
明确当前 transaction timestamp 与 actual current time 语义差异。

不要机械使用 `NOW()`，
必须理解 PostgreSQL transaction timestamp semantics。

对于 short heartbeat/claim transaction，
选择明确的数据库当前时间 authority，
并 ADR 冻结。

============================================================

server restart
lease expiry
stale worker
retry
cancel
partial semantic completion

也不会：

丢任务
重复 authoritative ownership
让旧 Worker覆盖新事实
制造第二套 Research semantic truth
无限重试

而是最终收敛到：

COMPLETED
FAILED

“服务器不会忘记这个 Research。”

P8.2 必须回答：

“无论执行进程怎样中断，

把这个 Research可靠推进到真实最终状态。”

只有做到这一点，

P8.3 的 Command API
才应该成为一个薄 HTTP control boundary，

重新塞进 API process。
