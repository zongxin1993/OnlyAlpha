2. 当前阶段的目标定义
======================================================================

P7.6.1 的目标不是：

“把 coverage 从 99.x% 改成 100%。”

真正目标是：

关闭 P7.6 引入 Factor Definition Resolver 之后暴露出的
verification ownership gap。

原则：

Production semantic contract
必须由 contract owner 自己拥有正式验证。

官方 Factor plugin 当前拥有：

- Factor Type Definition
- parameter semantics
- input/output semantics
- warmup semantics
- missing semantics
- timestamp semantics
- numeric semantics
- RESEARCH backend
- Definition Resolver

因此：

Factor Definition Resolver 的 semantic correctness
必须被 research-factor owner lane 直接验证。

不能只依赖：

research-sweep tests

间接经过 Resolver 代码。

最终关系应为：

Calculation Registry
    ↓
验证 generic resolver contract

Official Factor Plugin
    ↓
验证 exact Factor-owned resolver semantics

Research Sweep
    ↓
验证 resolver 可以参与 composition

三层责任不能互相替代。

6. 必须增加的核心验证
======================================================================

至少完成以下 semantic verification。

----------------------------------------------------------------------
6.1 Official Factor registration completeness
----------------------------------------------------------------------

验证所有 official Factor registrations：

- backend == RESEARCH
- definition_resolver is not None
- definition_resolver.type_definition == registration.type_definition

目标：

以后增加 official Factor 时，不能只注册 backend 而漏掉 Definition Resolver。

形成不变量：

Official parameterized Research Factor
=
exact type definition
+
RESEARCH backend
+
Definition resolver

----------------------------------------------------------------------
6.2 Momentum direct resolution 与 Registry re-materialization 等价
----------------------------------------------------------------------

针对 official Momentum Factor。

构造明确输入，例如：

short_weight = 0.25
long_weight = 0.75

return_short -> upstream A
return_long  -> upstream B

Path A：

通过 official direct resolver，例如：

resolve_momentum(...)

生成 Definition。

Path B：

构造 OnlyCalculationRegistry，
注册 official Factor registrations，
通过：

registry.rematerialize_definition(...)

生成 Definition。

必须证明：

definition_direct == definition_rematerialized

并明确验证至少：

- kind
- type_id
- semantic_version
- parameters
- input bindings
- inputs
- outputs
- warmup
- missing policy
- timestamp semantic
- numeric semantics
- factor_kind
- extensions（如果正式 contract 存在）
- fingerprint

最终必须：

direct.fingerprint == rematerialized.fingerprint

----------------------------------------------------------------------
6.3 Cross-Section Percentile direct resolution 与 re-materialization 等价
----------------------------------------------------------------------

针对：

cross_section_percentile

使用能够触发 normalization 的输入，例如：

direction = "lower_is_better"

如果正式 ParameterSchema 会 uppercase，则必须证明最终 resolved value 是：

LOWER_IS_BETTER

并验证：

direct resolve
==
Registry re-materialization

必须证明 Resolver 确实重新进入 type-owned ParameterSchema normalization，
不是简单保存 caller raw parameter。

同样比较完整 Definition 与 fingerprint。

----------------------------------------------------------------------
6.4 Input binding identity propagation
----------------------------------------------------------------------

验证 Resolver 不只是重建 parameters，也重新消费 composition input bindings。

例如 Momentum：

第一次：

return_short -> A
return_long  -> B

第二次：

return_short -> C
return_long  -> D

parameters 相同。

必须证明：

input bindings 正确进入 resolved Definition。

并且：

same parameters
+
different semantic upstream bindings
→
different Definition identity

即 fingerprint 必须变化。

不能只 assert parameters。

----------------------------------------------------------------------
6.5 Parameter identity propagation
----------------------------------------------------------------------

例如 Momentum：

Case A:

short_weight=0.5
long_weight=0.5

Case B:

short_weight=0.25
long_weight=0.75

input bindings 相同。

必须证明：

Definition A != Definition B
fingerprint A != fingerprint B

同时：

- type_id
- semantic_version
- Factor kind
- output contract
- numeric semantics

等不应被参数变化意外破坏。

----------------------------------------------------------------------
6.6 Complete semantics preservation
----------------------------------------------------------------------

测试不得只比较 parameters。

必须证明 Resolver 重建的是完整 resolved Definition。

至少关注：

parameters
input bindings
warmup
missing policy
timestamp
numeric
Factor execution shape
input/output semantic types

尤其保护：

resolved Definition
不是：

replace(old_definition, parameters=...)

而是通过正式 type-owned resolver 完整重建。

----------------------------------------------------------------------
6.7 Fail-closed path
----------------------------------------------------------------------

至少通过 Registry re-materialization 路径验证一个或多个非法 semantic request。

例如：

Momentum：

hidden_period = 20

应 fail closed。

Percentile：

direction = SIDEWAYS

应 fail closed。

错误不必重新设计，只需保持现有稳定 validation behavior。

目标：

证明：

Registry
→ Definition Resolver
→ Factor-owned validation

没有绕过 ParameterSchema 和 Factor contract。

    └── verifies semantics

Factor-owned Definition Resolver
不再只是被 Sweep 偶然调用的 implementation detail，
而成为 official Factor 自己正式拥有、持续验证的 semantic contract。

在不改变任何既有 Research identity / authority 的前提下，

为 P7.7 的 Research Evaluation 工作提供一个干净、绿色、可信的基线。
