==================================================
三、第一性原理：必须建立的 5 条不变量
==================================================

整个实现必须围绕以下不变量设计。

--------------------------------------------------
Invariant 1 — Single Semantic Writer
--------------------------------------------------

Streaming Runtime 中所有 MarketData semantic mutation 必须通过唯一的串行 processing authority。

包括：

- normal realtime update
- historical recovery update
- buffered realtime catch-up update

禁止出现多个直接调用：

MarketDataProcessor.process(...)

的旁路。

最终应尽量做到：

Streaming Runtime 中只有一个明确的 processing component 可以进入 MarketDataProcessor。

--------------------------------------------------
Invariant 2 — Stop Has Precedence
--------------------------------------------------

一旦 STOPPING 被建立：

不得再开始新的 MarketData semantic mutation。

要求定义清楚 processing cutoff：

Processing Authority revoke 返回以后：

- 不允许新的 MarketDataProcessor.process
- 不允许新的 Bar-driven semantic mutation
- 不允许 recovery history apply
- 不允许 buffered suffix apply
- 不允许由新 Bar 触发 Strategy/Broker semantic progress

已经进入 atomic semantic processing 的一个 update 可以完成；
但之后绝不能开始下一个 update。

不能依赖：

if not stop_requested:
    processor.process(...)

这种 check-then-act。

check 和进入 semantic mutation 必须由同一个同步 authority 原子保护。

--------------------------------------------------
Invariant 3 — External I/O != Semantic Authority
--------------------------------------------------

Historical DataSource 的 load_bars / recovery read：

只负责获取 external facts。

它不能：

- 持有 processing permission lock
- 调用 MarketDataProcessor
- 修改 Trading Kernel
- 修改 Broker
- 修改 Strategy
- 决定 Runtime domain facts

Historical I/O 可以阻塞。

但阻塞期间：

STOP 必须能够建立 processing cutoff。

如果 STOP 在 Historical I/O 阻塞期间发生：

I/O 返回后的 recovery batch 必须被 discard，
不能产生任何 late semantic mutation。

--------------------------------------------------
Invariant 4 — Recovery Is Forward Replay
--------------------------------------------------

Recovery 的正确模型必须保持：

Confirmed Frontier
→ determine missing closed-Bar boundaries
→ historical load
→ strict validation
→ deterministic normalization
→ replay through SAME MarketData processing lane
→ reconcile buffered realtime suffix
→ continuity proof
→ LIVE

不要建立第二套 recovery semantic pipeline。

不要创造特殊的“恢复状态直接写 Trading State”路径。

--------------------------------------------------
Invariant 5 — Test Time != Business Semantics
--------------------------------------------------

测试中的 timeout 只是：

deadlock / stuck-operation watchdog

不是：

产品正确性条件或性能 SLA。

禁止用“必须在 3 秒内 recovery 完成”作为 correctness contract。

异步状态测试应优先使用：

- Condition
- Event
- phase revision
- deterministic synchronization point

而不是短时间 polling。

==================================================
五、实现 1：Streaming Processing Authority
==================================================

当前 Worker 内部已经有 processing permission lock / stop Event 的概念。

将这个概念提升为明确的 Streaming Processing Authority。

建议抽象：

OnlyStreamingProcessingLane

职责：

1. 唯一拥有进入 MarketDataProcessor 的权限。
2. 串行化所有 streaming MarketData semantic processing。
3. 建立 revoke / stop cutoff。
4. 确保 processor mutation 与 Runtime 对该 processing result 的必要 bookkeeping 构成一致的 atomic processing step。

建议概念 API：

class OnlyStreamingProcessingLane:

    def process(
        self,
        update,
        commit_result,
    ) -> OnlyStreamingProcessingOutcome:
        ...

    def revoke(self) -> None:
        ...

    @property
    def revoked(self) -> bool:
        ...

关键语义：

with permission_lock:

    if revoked:
        return NOT_STARTED

    result = processor.process(update)

    commit_result(update, result)

    return STARTED(result)

注意：

commit_result 只能做本次 semantic processing 对应的确定性 Runtime bookkeeping。

例如：

- processing_results
- latest_bars
- accepted_market_sequences
- processed identities
- last closed bar frontier
- deterministic observation bookkeeping

不要让 commit_result：

- 执行 Historical I/O
- 执行 recovery orchestration
- reconnect
- block for external provider

==================================================
六、Worker callback 必须拆成 semantic commit 与 control reaction
==================================================

不要保持类似：

_handle_worker_result():
    _record_processing_result()
    if GAP:
        _recover_gap()

然后让 recovery 在 semantic processing critical section 中运行。

正确模型：

ProcessingLane:
    processor.process
    record_processing_result
    leave processing permission

之后：

if result.status == GAP_DETECTED:
    trigger recovery control flow

也就是说：

Semantic/Data Plane

和

Recovery Control Plane

必须明确分离。

Historical recovery 不得在 processing lock 内执行。

==================================================
七、实现 2：Streaming Phase Authority
==================================================

当前如果 OnlyStreamingRuntime 到处直接：

self._streaming_phase = ...

则 lifecycle authority 太分散。

建立明确：

OnlyStreamingPhaseController

至少负责：

- current phase
- transition serialization
- STOPPING precedence
- revision
- Condition notification
- state waiting

建议：

@dataclass(frozen=True)
class OnlyStreamingPhaseSnapshot:
    phase: OnlyStreamingPhase
    revision: int

接口概念：

snapshot()

transition(
    expected: set[OnlyStreamingPhase],
    target: OnlyStreamingPhase,
) -> bool

begin_stop() -> bool

complete_stop(...)

wait_for(
    target,
    *,
    after_revision=None,
    timeout=None,
)

最重要的不变量：

一旦进入 STOPPING：

Recovery 不允许再将 phase 改成：

- DEGRADED
- RECOVERING
- CATCH_UP
- LIVE

只允许：

STOPPING → STOPPED

或 shutdown failure 情况：

STOPPING → FAILED

STOP 必须具有 lifecycle precedence。

避免：

Thread A:
    STOPPING

Thread B:
    RECOVERING

最终 Thread B 覆盖 STOPPING。

八、实现 3：Recovery Loader
==================================================

当前 recovery historical loading/validation 的算法方向是正确的。

保留：

- calendar-aware expected closed-Bar boundaries
- HistoricalBarRequest
- instrument identity validation
- BarType validation
- DataVersion validation
- closed Bar validation
- calendar session validation
- exact coverage validation
- conflicting duplicate rejection
- deterministic recovery sequence normalization
- provider_sequence metadata
- recovery_generation metadata

但把它整理成独立 external-fact component：

OnlyStreamingRecoveryLoader

概念：

load(
    plan,
    accepted_sequence,
) -> OnlyStreamingRecoveryBatch

OnlyStreamingRecoveryBatch 应 immutable。

RecoveryLoader 可以依赖：

- HistoricalDataSource
- TradingCalendar / boundary helper
- DataVersion
- runtime/source identity required for normalized facts

RecoveryLoader 禁止依赖：

- MarketDataProcessor
- Broker
- Trading Kernel
- Strategy
- Runtime phase mutation
- Position/Order authority

核心原则：

RecoveryLoader produces facts.
It never applies facts.

九、重写 Recovery Orchestration
==================================================

OnlyStreamingRuntime._recover_market_continuity 类似方法最终应只负责 orchestration。

目标流程：

1.
install immutable recovery plan

2.
reset finalizer pending state if required

3.
DEGRADED → RECOVERING

4.
RecoveryLoader.load(plan)

注意：
load 可能阻塞。
此时不能持有 ProcessingLane lock。

5.
load 返回

检查 ProcessingLane 是否已经 revoke / phase 是否 STOPPING。

如果 STOP 已发生：

discard batch
return

不得 apply late recovery history。

6.
将 historical recovery updates 逐个通过：

OnlyStreamingProcessingLane.process(...)

处理。

不能 Runtime 直接：

market_data_processor.process(...)

7.
每个 recovery update 必须满足 expected result。

原则上 historical missing facts 应 APPLIED。

异常：
fail closed。

8.
RECOVERING → CATCH_UP

9.
drain realtime buffered suffix

10.
deterministically order / normalize suffix

11.
同样通过：

OnlyStreamingProcessingLane

处理。

12.
处理 drain 后新到 suffix，直到形成 continuity stable frontier。

13.
verify recovery complete

必须继续检查：

- recovery plan identity
- inbound suffix reconciled
- source connected
- subscription active
- worker alive
- market session / stale semantics
- expected frontier
- no secondary unresolved gap

14.
clear recovery plan

15.
CATCH_UP → LIVE

只有 explicit continuity proof 成功之后才允许 LIVE。

==================================================
十、STOP 实现要求
==================================================

目标 stop 语义：

Runtime.stop()

    PhaseController.begin_stop()
        ↓
    STOPPING established
        ↓
    ProcessingLane.revoke()
        ↓
    no future semantic processing can start
        ↓
    unsubscribe / source termination
        ↓
    worker stop
        ↓
    observation publisher stop
        ↓
    trading runtime stop
        ↓
    STOPPED

最关键的定义：

ProcessingLane.revoke() 返回以后，
不能再开始任何新的 MarketData semantic processing。

Historical I/O 如果仍在进行：

允许它之后返回，
但它的结果必须由于 revoked 被丢弃。

不要尝试强行 kill Python thread。

不要通过 daemon thread 掩盖 lifecycle 问题。

1.

预期：

- STOPPING 成功建立
- processing revoked
- historical result 之后返回

4.
gap detection racing with stop

5.
incomplete historical coverage

仍必须：

FAILED
fail closed

不能 silent discard。

6.

仍必须 fail closed。

7.
successful reconnect

必须：

- source connected
- continuity proof
- LIVE

8.

必须：

- order identity 不变
- exactly one fill
- no duplicate fill
- no synthetic cancel/reject

9.
gap trigger

GAP_DETECTED

10.
No late mutation after STOP cutoff
