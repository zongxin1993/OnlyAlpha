# 1. 第一性原则

开始编码前，必须先从系统不变量推导实现，不要从“让测试变绿”出发。

## 1.1 Admission 与 Execution 必须证明同一件事

Research Run 的实际语义链是：

```text
Exact Research Specification
        ↓
resolve
        ↓
Admission
        ↓
durable Run
        ↓
Worker load
        ↓
re-resolve
        ↓
verify admission evidence
        ↓
OnlyEngine
        ↓
OnlyResearchRuntime
        ↓
actual Calculation backend execution
```

系统真正需要保证：

```text
被 Admission 验证过的 semantic composition
==
实际 Runtime 执行使用的 semantic composition
```

形式化为：

```text
Resolve(S, C)
→ Verify
→ Execute(S, C)
```

其中：

- `S` = exact Research Specification
- `C` = 当前 Worker process 已建立的 Calculation composition

禁止实际结构继续是：

```text
Resolve(S, C1)
→ Verify
→ Execute(S, C2)
→ hope(C1 == C2)
```

即使 `C1` 与 `C2` 通常相同，也不构成结构性确定性。

正确系统应做到：

```text
不存在第二个 C2。
```

## 1.2 唯一性原则

本任务讨论的是：

```text
Worker Process Composition Authority
```

它不是新的 durable domain authority。

它表示：

> 一个已启动的 Research Worker 进程，到底认可哪一组 Runtime factories、Calculation type definitions、semantic versions、backend registrations 和 providers。

必须满足：

```text
One Worker Process
→ One Startup Composition
→ One Calculation Registry
```

并且：

```text
Resolver
和
OnlyEngine / OnlyResearchRuntime

共同消费这个唯一 Registry。
```

禁止：

```text
Worker startup Registry A
+
per-claim Engine Registry B
```

## 1.3 确定性原则

必须消除：

```text
同一 Worker 生命周期内重新 discovery / 重新 composition
```

产生的自由度。

正确 deterministic contract：

```text
Worker W starts at T0
Composition(W) = C

对于 W 执行的所有 Attempts：

Resolve(S, C)
Execute(S, C)
```

直到 Worker restart，才允许重新建立新的进程级 composition。

## 1.4 共享 Composition，不共享 mutable execution world

“单一 Composition”绝不等于“复用同一个 Engine”。

必须保持：

```text
Process lifetime:
    EngineServices
    CalculationRegistry
    plugin composition
    ↓
    long-lived

Attempt lifetime:
    fresh OnlyEngine
    fresh OnlyResearchRuntime
    fresh runtime execution state
    ↓
    short-lived
```

必须保持：

```text
services identity stable
engine identity fresh
runtime identity fresh
```

禁止为了唯一性变成：

```text
one Worker
→ one mutable OnlyEngine
→ multiple Runs reuse one Engine lifecycle
```

## 1.5 解决 root cause，不污染 semantic identity

当前问题不是：

```text
Admission fingerprint 信息不够多
```

而是：

```text
Admission 和 Execution 没有被结构性地绑定到同一个 composition。
```

因此禁止通过把以下 implementation identity 塞进 semantic fingerprint 来解决：

```text
Python class path
module path
provider repr
object id
entry-point object
process id
package installation path
```

必须继续保持：

```text
semantic identity
!=
implementation object identity
```

# 4. 当前已知 Root Cause

在此前主线实现中，Research Worker startup 存在独立 `_registry()`：

```text
worker_main
    ↓
new CalculationRegistry A
    ↓
only_discover_plugins(...)
    ↓
Specification Resolver
```

而真正执行 Run 时：

```text
OnlyEngineResearchRuntimeExecutor
    ↓
new OnlyEngine(...)
    ↓
OnlyEngine._require_services()
    ↓
only_default_engine_services()
    ↓
new CalculationRegistry B
    ↓
only_discover_plugins(...)
    ↓
OnlyResearchRuntime
```

于是形成：

```text
Registry A
→ Specification re-resolution
→ admission evidence verification

Registry B
→ actual Research backend execution
```

这不是第二个 durable authority，但它违反：

```text
single process composition
+
execution determinism
```

因为正确性依赖：

```text
A 应该和 B 一样
```

而不是：

```text
A 和 B 结构上就是同一个 composition。
```

---

# 5. 为什么“两次 discovery 应该一样”不能接受

系统 correctness 不能建立在：

```text
正常情况下两次 importlib.metadata discovery 应该得到相同结果
```

之上。

`only_discover_plugins()` 会：

```text
enumerate entry points
load entry point
instantiate factory/provider
register result
fail fast on errors
```

因此 discovery 是有真实行为的 composition operation。

第一性原则要求：

```text
不要证明两次 discovery 相等。
直接删除第二次 discovery。
```

# 6. 推荐生产实现

## 6.1 使用现有 OnlyEngineServices

不要发明新的 Research-specific composition authority。

当前 Engine 已有正式 composition abstraction：

```python
OnlyEngineServices
```

并且：

```python
OnlyEngine(
    config,
    services=services,
)
```

已经支持显式注入。

应直接复用。

## 6.2 Worker startup 建立一次 EngineServices

目标结构：

```python
services = only_default_engine_services(
    fail_fast=True,
)
```

然后取：

```python
calculations = services.assembler.components.calculations
```

这个 `calculations` 必须同时被：

```text
OnlyResearchSpecificationResolver
+
OnlyEngine
```

消费。

## 6.3 删除 worker_main 本地 `_registry()` composition

原则上删除此前类似：

```python
def _registry() -> OnlyCalculationRegistry:
    calculations = OnlyCalculationRegistry()

    only_discover_plugins(
        OnlyDataSourceFactoryRegistry(),
        OnlyBrokerFactoryRegistry(),
        OnlyBrokerFeeContractRegistry(),
        OnlyMarketProductFactoryRegistry(),
        calculations,
        fail_fast=True,
    )

    only_register_research_predicate_primitives(calculations)

    return calculations
```

并清理仅因此存在的 imports。

`worker_main.py` 不应该拥有一套与 Engine 默认 composition 平行的 registry construction。

## 6.4 Resolver 使用 Services 中唯一 CalculationRegistry

目标：

```python
services = only_default_engine_services(
    fail_fast=True,
)

calculations = services.assembler.components.calculations

resolver = OnlyResearchSpecificationResolver(
    calculations
)
```

这样：

```text
Resolver Registry
==
EngineServices Calculation Registry
```

不是内容相等，而是同一 process-level composition source。

## 6.5 Runtime Executor 接收同一个 EngineServices

当前或此前：

```python
class OnlyEngineResearchRuntimeExecutor:
    def __init__(self, user_data_root: Path) -> None:
        self._user_data_root = user_data_root
```

应最小修改为类似：

```python
class OnlyEngineResearchRuntimeExecutor:
    def __init__(
        self,
        user_data_root: Path,
        services: OnlyEngineServices,
    ) -> None:
        self._user_data_root = user_data_root
        self._services = services
```

然后：

```python
engine = OnlyEngine(
    OnlyEngineConfig(
        OnlyEngineId("research-worker"),
        self._user_data_root,
    ),
    services=self._services,
)
```

不要让 Executor 自己：

```text
only_default_engine_services()
only_discover_plugins()
```

Executor 的职责是：

```text
fresh execution world
```

不是：

```text
new process composition
```
