# Execution reference inputs

Controlled hermetic inputs, never real market/account/deployment evidence. `domain-inputs.json` retains its frozen canonical bytes; the native Order fixture test derives the complete request and Order/Fee contracts from native owners and rejects byte drift. The old Python fixture writer is retired. `economics-v1.json` contains independent hand-derived nonzero cumulative-fee cash/cost expectations consumed by native real-component tests. `partial-close-v1.json` preserves the independently specified quantity, cost, cash, realized-PnL and incremental-fee values for the two-part 400-unit close. The native lifecycle test asserts the full records directly; the output checker reads the same literals without starting a legacy Python Runtime. Implementation/provenance identities are intentionally distinct. Fractional cumulative-PnL corrections are Rust-specific regressions, not claims of Python equivalence.

`reconciliation-v1.jsonl` supplies independent aggregate literals for configured genesis, Fill, profit/loss marks, realized close PnL and a real multi-Cluster rounding mismatch. Native tests build each source through the owning Execution protocol; the comparator checks the complete literal corpus without loading a Python backend. Exact residuals, complete source/identity guards and adversarial relations remain native invariants.

`backtest-result-v1.jsonl` contains hand-derived Result counts/equity/return expectations for empty single/multiple Cluster, zero capital and partial-fill/cancel cases. Native owners produce full source-bound records; the comparator validates independent literals and canonical content identities without loading a Python backend. Rust tests retain outcome-sensitive identity, source/recovery and economic assertions. It does not certify whole Runtime or Shipping UI equivalence.
